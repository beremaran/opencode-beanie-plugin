## OpenCode patterns

- Keep the public entrypoint loader-safe and minimal. `src/index.ts` re-exports the default plugin factory and a named alias, while the implementation remains in `src/plugin.ts` (`src/index.ts:1-8`). The package exposes both the root entry and `./plugin` subpath (`package.json:6-16`), which supports canonical and explicit plugin references.
- Register tools and hooks from one async plugin factory. The factory checks the external CLI, then returns seven tools (`remember`, `search_memory`, `ask_memory`, `memory_stats`, `timeline`, `forget`, `compact`) plus `chat.message` and `experimental.chat.system.transform` (`src/plugin.ts:101-112`, `:113-352`, `:354-491`). Tool schemas provide model-facing descriptions and typed arguments, while execution delegates to `Mind`.
- Use lifecycle hooks for cross-session behavior. `chat.message` extracts and deduplicates user intent, while the system transform appends memory guidance, recent context, relevant memories, and prior goals (`src/plugin.ts:354-395`, `:406-487`). This is a practical pattern for adding persistent context without requiring every tool call to carry it manually.
- Put stateful orchestration behind a singleton whose promise is cached. `getMind()` prevents concurrent callers from opening multiple stores and clears the cache when initialization fails, allowing a later retry (`src/core/mind.ts:394-415`). Per-agent chain and parent maps use size caps and oldest-entry eviction (`src/core/mind.ts:33-65`, `:171-185`; `src/constants.ts:18-28`).
- Isolate a non-JavaScript engine behind a typed adapter. All Rust-engine interaction is centralized in `MnemoriaCli`, which uses `execFile` argument arrays, parses known output formats, and exposes typed operations (`src/core/mnemoria-cli.ts:1-7`, `:123-162`, `:203-272`). This keeps OpenCode-facing code independent of process details.
- Package slash commands as first-class OpenCode assets. `package.json` includes `dist`, `commands`, and `install.sh` (`package.json:30-34`), and command front matter selects an agent and directs it to the corresponding tool (`commands/mn-search.md:1-7`, `commands/mn-forget.md:1-13`).

## Security and reliability lessons

- Prefer `execFile` over shell interpolation when invoking a CLI. User-controlled queries, summaries, content, and agent filters are passed as separate arguments rather than embedded in a shell command (`src/core/mnemoria-cli.ts:123-139`, `:207-225`, `:239-250`). This materially reduces command-injection risk.
- Bound external-process behavior. Commands have a 30-second timeout and 10 MB output buffer, transient failures receive bounded exponential retries, and permanent `ENOENT`/`EACCES` failures are not retried (`src/core/mnemoria-cli.ts:123-161`; `src/constants.ts:129-157`).
- Fail open for optional context hooks. Intent capture and prompt injection catch errors and log them instead of breaking the host session (`src/plugin.ts:397-403`, `:488-490`). This is appropriate for memory enrichment, but the logs can expose error text and should be reviewed if engine errors may contain sensitive paths or data.
- Use append-only tombstones for user-visible forgetting, then compact separately. `forget` writes an ID-based warning marker and rejects ambiguous summary matches (`src/core/mind.ts:189-219`, `:364-390`); compaction removes markers, referenced IDs, legacy summary matches, and optionally old entries (`src/core/mind.ts:310-361`). ID targeting is safer than summary-only deletion.
- Treat the rebuild path as a high-risk operation. The implementation writes a temporary store, but then removes the live store before `renameSync`; if both rename and copy fail after that removal, the original store is no longer intact despite the atomicity comment (`src/core/mnemoria-cli.ts:427-471`). A production implementation should use a same-filesystem swap protocol or retain a rollback backup.
- Avoid silently treating parser drift as valid data. Search and timeline warn when numbered output exists but no lines parse (`src/core/mnemoria-cli.ts:257-270`, `:334-347`), but stats instead returns zero/null values for unparseable output (`src/core/mnemoria-cli.ts:295-309`). Consumers could mistake a changed CLI format for an empty store.
- Consider prompt-injection and data-boundary risks in injected memory. Stored summaries and prior user-goal content are copied into the system prompt with only length/count limits (`src/plugin.ts:444-486`; `src/constants.ts:98-116`). The README says storage is local/offline (`README.md:312-319`), but local memories can still contain untrusted instructions or secrets; provenance markers, sanitization, and explicit trust boundaries would reduce that risk.
- The installer has a supply-chain and robustness tradeoff. The documented `curl ... | sh` path executes a remote script (`README.md:43-55`), and when local commands are unavailable the script downloads and extracts the moving `main` archive without a commit or checksum pin (`install.sh:126-131`). It also only edits an existing config automatically when `jq` is present; otherwise it warns and leaves configuration unchanged (`install.sh:83-96`).
- Tool inputs are schema-described but not strongly bounded at the OpenCode boundary. Summary is truncated before storage, but content and several numeric options flow through without explicit range checks (`src/plugin.ts:114-128`, `:231-269`, `:330-349`; `src/core/mind.ts:105-133`). Add limits for content size, result limits, age values, and timestamps before passing them to the CLI.

## Testing lessons

- Separate plugin contract tests from engine integration tests. `plugin.test.ts` mocks the OpenCode tool helper and CLI constructor, then checks tool registration, hook presence, agent defaults, wildcard rejection, forgetting, compaction, and hook behavior (`src/plugin.test.ts:5-80`, `:104-126`, `:128-272`, `:274-345`).
- Test the process boundary with controllable `execFile` mocks. `mnemoria-cli.test.ts` replaces Node process/filesystem APIs and verifies command arguments, output parsing, filters, and fallback behavior (`src/core/mnemoria-cli.test.ts:12-47`, `:70-221`, `:224-320`). This is a strong no-network/no-binary unit-test pattern.
- Include real-binary tests, but skip them explicitly when the prerequisite is unavailable. The integration suite uses a temporary store, tests init/add/search/stats/timeline/export/verify/enrichment/agent filtering, and applies `describe.skipIf(!binaryAvailable)` (`src/core/mnemoria-cli.integration.test.ts:1-9`, `:21-45`, `:47-117`). Skipping is useful for ordinary CI, but a release lane should require the binary so integration coverage cannot remain permanently unexecuted.
- Test pure heuristics independently. Helper tests cover ID format/uniqueness, token estimation, truncation, intent categories, path extraction, thresholds, and scoring (`src/utils/helpers.test.ts:9-20`, `:23-77`, `:79-163`). Mind tests cover custom paths, chain IDs, ID-based forget, ambiguous summaries, and compaction (`src/core/mind.test.ts:46-63`, `:108-145`, `:194-315`).
- Current verification in this corpus environment is unavailable: `npm test` failed before test execution with `sh: vitest: command not found`; `npm run typecheck` failed because all test files cannot resolve `vitest` (`src/plugin.test.ts:1`, `src/core/mind.test.ts:1`, `src/core/mnemoria-cli.test.ts:1`, `src/core/mnemoria-cli.integration.test.ts:11`, `src/utils/helpers.test.ts:1`). These are missing-dependency failures, not assertion failures.

## Packaging and release lessons

- Use strict TypeScript and reproducible package scripts. The project enables strict checking, declarations, source maps, bundler resolution, and isolated modules (`tsconfig.json:1-19`); `check` composes typecheck, lint, and tests, while `prepublishOnly` builds (`package.json:18-28`).
- Build both public entry surfaces explicitly. `tsup` emits ESM, declarations, and source maps for `src/index.ts` and `src/plugin.ts`, bundles the OpenCode plugin dependency, and cleans only on the first build target (`tsup.config.ts:1-22`).
- CI separates typecheck, lint, tests, and build, with build depending on the first three and checking all expected `dist` artifacts (`.github/workflows/ci.yml:12-66`). This gives useful failure attribution and catches packaging omissions.
- Add recurring dependency and license audits. The audit workflow runs on pushes, pull requests, and weekly schedule, using `npm audit --omit=dev` and a production license denylist (`.github/workflows/audit.yml:1-40`; `package.json:25-28`).
- Gate npm publication on verification and package inspection. Release verification runs `npm run check`, builds, runs `npm pack --dry-run`, and requires a release tag matching `package.json`; publishing uses npm provenance (`.github/workflows/release.yml:12-40`, `:42-64`).
- Keep the install surface coherent with the package surface. The package requires Node >=18 and declares the OpenCode plugin dependency as a dev dependency because the bundler embeds it (`package.json:61-73`; `tsup.config.ts:11-20`). The runtime also requires a separately installed Rust `mnemoria` binary (`README.md:37-55`), so installation documentation and release verification must cover both artifacts.

## Recommended takeaways

1. Keep the entrypoint thin; register tools/hooks in a factory and isolate external processes behind typed adapters.
2. Use argument-safe process execution, bounded retries/timeouts, and explicit parser-drift warnings.
3. Treat prompt-injected memory as untrusted content, and bound all tool inputs before persistence or CLI execution.
4. Make compaction truly recoverable; never remove the live store without a rollback path.
5. Pair mocked boundary tests with a required real-binary integration lane, and treat missing dependencies as verification failures rather than passing results.
6. Pin installer downloads and validate package contents, runtime dependencies, security audits, licenses, and release tags before publication.
