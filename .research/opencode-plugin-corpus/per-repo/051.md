## OpenCode Patterns

- **Separate server and TUI entrypoints.** The server plugin exports the required identity but intentionally performs no server work (`server: async () => ({})`) ([`src/index.ts:1-8`](../repos/mark1708--opencode-agents-sidebar/src/index.ts#L1-L8)). The package exposes `.` as `dist/index.js` and `./tui` as `dist/tui.js`, and marks the TUI plugin with `oc-plugin: ["tui"]` ([`package.json:29-39`](../repos/mark1708--opencode-agents-sidebar/package.json#L29-L39)). This is a useful pattern when functionality belongs entirely in the host TUI lifecycle.
- **Provider boundary before native discovery.** `loadAgentSources()` constructs provider context, loads OhMyOpenAgent and custom providers concurrently, and merges their normalized states ([`src/providers/index.ts:12-29`](../repos/mark1708--opencode-agents-sidebar/src/providers/index.ts#L12-L29)). The custom provider is currently an explicit empty seam ([`src/providers/custom.ts:1-7`](../repos/mark1708--opencode-agents-sidebar/src/providers/custom.ts#L1-L7)), while the bootstrap provider maps local configuration into a common `AgentEntry` shape ([`src/providers/omo.ts:112-140`](../repos/mark1708--opencode-agents-sidebar/src/providers/omo.ts#L112-L140)).
- **Lifecycle-safe TUI registration.** The TUI module loads initial state, registers file watchers with a polling fallback, registers `onDispose` cleanup for watchers/timers, and inserts content through `sidebar_content` with configurable slot order ([`src/render.ts:274-287`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L274-L287), [`src/render.ts:328-390`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L328-L390)). Clickable rows and headers use `box` plus `onMouseDown`, not text nodes ([`src/render.ts:107-123`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L107-L123)).
- **Explicit host-facing state.** Missing, invalid, loaded, and diagnostic conditions are rendered as user-visible states rather than thrown through the UI; loaded states distinguish provider errors from "no agents" and "all hidden or disabled" ([`src/render.ts:165-172`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L165-L172), [`src/render.ts:230-245`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L230-L245)).

## Implementation Lessons and Pitfalls

- **Normalize and deduplicate at the boundary.** Duplicate names are canonicalized by trimmed, underscore-to-hyphen, case-insensitive keys; the winner policy prefers custom and OpenCode sources and preserves a structured warning about the ignored source ([`src/agents/merge.ts:4-17`](../repos/mark1708--opencode-agents-sidebar/src/agents/merge.ts#L4-L17), [`src/agents/merge.ts:20-45`](../repos/mark1708--opencode-agents-sidebar/src/agents/merge.ts#L20-L45)). This avoids silently losing provenance, but name-based identity means two providers cannot intentionally expose same-named agents independently.
- **Be strict at the untrusted JSON boundary.** Config readers accept `unknown`, validate records, finite numbers, booleans, enums, string arrays, and string-only alias values, then merge into fresh defaults ([`src/config.ts:7-58`](../repos/mark1708--opencode-agents-sidebar/src/config.ts#L7-L58)). The OhMyOpenAgent coercion layer applies the same discipline to agent, fallback, team, tmux, and TUI fields ([`src/providers/omo.ts:217-253`](../repos/mark1708--opencode-agents-sidebar/src/providers/omo.ts#L217-L253), [`src/providers/omo.ts:256-342`](../repos/mark1708--opencode-agents-sidebar/src/providers/omo.ts#L256-L342)).
- **Provider-specific categories should not leak into generic grouping.** OhMyOpenAgent lifecycle names are mapped in its provider adapter, while generic agents fall back to `Custom` or `Other` ([`src/providers/omo.ts:68-105`](../repos/mark1708--opencode-agents-sidebar/src/providers/omo.ts#L68-L105), [`src/agents/categories.ts:8-12`](../repos/mark1708--opencode-agents-sidebar/src/agents/categories.ts#L8-L12)). A maintenance hazard is that `groupByCategory()` groups on the already-materialized `agent.category` and does not itself call `resolveGenericCategory()` ([`src/agents/categories.ts:14-26`](../repos/mark1708--opencode-agents-sidebar/src/agents/categories.ts#L14-L26)); every provider must therefore supply a valid category.
- **Polling and watchers need state-transition care.** File events are debounced and watcher failure falls back to polling ([`src/render.ts:251-287`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L251-L287)), while reloads compare serialized agent/provider/path state before requesting a render ([`src/render.ts:259-271`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L259-L271), [`src/render.ts:323-326`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L323-L326)). However, the watcher set is created once from the initial state ([`src/render.ts:349-350`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L349-L350)); a future provider that changes its watched paths would need explicit watcher re-registration.
- **Errors are intentionally quiet in the reload path.** `createReload()` catches all reload errors and returns without updating state or requesting a render ([`src/render.ts:259-271`](../repos/mark1708--opencode-agents-sidebar/src/render.ts#L259-L271)). This protects the TUI from crashes but can leave stale data with no visible diagnostic; production providers should surface reload failures through state or logging.
- **Display safety is treated as a contract.** Control characters are replaced before width truncation, and all formatted lines are bounded ([`src/config.ts:101-106`](../repos/mark1708--opencode-agents-sidebar/src/config.ts#L101-L106), [`src/format.ts:5-12`](../repos/mark1708--opencode-agents-sidebar/src/format.ts#L5-L12)). This is important because agent names, model refs, diagnostics, and config-derived labels are rendered in a terminal.

## Security

- The plugin reads local metadata from the fixed user path `~/.config/opencode/oh-my-openagent.json` ([`src/config.ts:1-5`](../repos/mark1708--opencode-agents-sidebar/src/config.ts#L1-L5)); it does not read provider credentials, and the README explicitly describes the source as metadata-only ([`README.md:259-265`](../repos/mark1708--opencode-agents-sidebar/README.md#L259-L265)).
- JSON parsing is guarded: missing files become a missing state, malformed JSON becomes an invalid state, and non-object JSON is rejected ([`src/config.ts:76-93`](../repos/mark1708--opencode-agents-sidebar/src/config.ts#L76-L93)).
- Terminal injection risk is reduced by `sanitizeLine()` and truncation before rendering ([`src/config.ts:101-106`](../repos/mark1708--opencode-agents-sidebar/src/config.ts#L101-L106), [`src/format.ts:5-12`](../repos/mark1708--opencode-agents-sidebar/src/format.ts#L5-L12)). The remaining trust boundary is the local config file itself: any user or process able to modify it controls displayed labels and diagnostics.
- CI writes the npm token to a temporary `.npmrc`, publishes only on semantic-version tags, and removes the file afterward ([`.gitlab-ci.yml:38-49`](../repos/mark1708--opencode-agents-sidebar/.gitlab-ci.yml#L38-L49)). This is preferable to committing credentials, though the pipeline should still rely on protected CI variables and runner isolation.

## Overall Assessment

This is a focused provider-normalization and TUI-rendering foundation with unusually clear boundaries, defensive config parsing, deterministic duplicate handling, terminal-safe formatting, and a useful pure-function test suite. The main risks are architectural rather than security-critical: native OpenCode discovery is not yet implemented ([`README.md:56-56`](../repos/mark1708--opencode-agents-sidebar/README.md#L56-L56)), the custom provider is only a placeholder, reload failures are swallowed, and the real TUI lifecycle is not covered by tests. Packaging is coherent and CI-gated, but typecheck/build reproducibility requires the declared peer dependencies to be installed in the build environment.
