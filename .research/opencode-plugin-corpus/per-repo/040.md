## OpenCode integration patterns

- Keep the plugin entry module to one default export. `index.ts` explicitly explains that OpenCode invokes every function-valued entry export as a factory and exports only `default`, while named test/helpers remain in the transitive `impl.ts` module (`index.ts:3-16`). This is a useful loader-compatibility pattern and avoids silently registering helper functions as plugins.
- Return a `tool` plus a display hook from the plugin factory. `impl.ts` creates `morph_edit` with `tool(...)` and implements `tool.execute.after` to set branded TUI titles and metadata (`impl.ts:234-344`, `impl.ts:347-405`). The hook is presentation-oriented and does not alter execution semantics.
- Put routing guidance in both the tool description and an always-on instruction file. The embedded description distinguishes `morph_edit`, native `edit`, and `write`, while `instructions/morph-tools.md` calls itself the canonical policy and recommends the OpenCode `instructions` array rather than a skill (`impl.ts:244-280`; `instructions/morph-tools.md:1-8`, `18-39`). This reduces tool-selection ambiguity without forcing the Morph tool for every edit.
- Document tool exposure as a separate requirement. The packaged instruction warns that an agent must expose `morph_edit: true`; loading instructions alone cannot make an unavailable tool selectable (`instructions/morph-tools.md:59-68`; `README.md:64-71`).
- Inject runtime dependencies into the execution core. `executeMorphEdit` receives filesystem, API, logging, time, path-resolution, parsing, diff, and configuration dependencies through `ExecuteMorphEditRuntime`, explicitly enabling no-network unit tests (`src/execute.ts:11-69`).

## Security and reliability lessons

- Confine file writes to the active root before reading or writing. Execution selects an ADV capability root, worktree, session directory, or plugin directory, then rejects paths outside the resolved root (`src/execute.ts:111-122`). The confinement helper uses separator-aware containment instead of a naïve string prefix and follows symlinks for existing targets and nearest existing parents for new targets (`src/path-confinement.ts:14-26`, `48-60`, `81-121`).
- Treat delegated worktree roots as capabilities and fail closed on malformed values. `readCapabilityRoot` accepts only an absolute string root, catches hostile accessors/proxies, and returns `null` so normal session-root confinement remains in force (`src/adv-capability.ts:3-35`). Tests cover valid capability confinement, fallback, malformed capabilities, and independent concurrent roots (`index.test.ts:1942-2042`, `2067-2100`).
- Prevent accidental full-file deletion from marker omission. Existing files over 10 lines without the lazy marker are refused; files over 3 lines produce a warning; new files require complete content without markers (`src/execute.ts:129-163`). The distinction is documented in the README as a pre-flight deletion guard (`README.md:9-18`, `167-181`) and tested for refusal and intentional small-file replacement (`index.test.ts:1230-1273`).
- Validate model output before committing it. The execution path blocks marker leakage, dual-threshold catastrophic truncation (>60% characters and >50% lines), and dropped top-level import identifiers before `writeFile` (`src/execute.ts:184-246`). No-marker replacements use the supplied edit as the truncation baseline, avoiding a false comparison against the old file (`src/execute.ts:199-220`). Tests explicitly assert no write for unsafe output and permit a genuine replacement (`index.test.ts:1275-1450`).
- Scrub secrets at every external-error boundary. `scrubSecrets` safely normalizes unknown values, redacts the configured key only when it is a non-empty string, and redacts generic Bearer tokens (`impl.ts:41-65`). API HTTP and request errors pass through it, while timeout and parse classifications remain stable (`impl.ts:131-197`). Tests cover API keys, Bearer tokens, nullish/numeric/unstringifiable values, HTTP errors, invalid JSON, and body-parse aborts (`index.test.ts:1552-1609`, `1652-1728`).
- Bound the complete HTTP response lifecycle. The AbortController timeout remains active through fetch, error-body reading, and JSON parsing; body-parse aborts are classified as `api_timeout`, not a misleading parse error (`impl.ts:74-79`, `108-169`; `index.test.ts:1702-1728`).
- Do not expose write capability to readonly agents by default. `plan` and `explore` are blocked unless `MORPH_ALLOW_READONLY_AGENTS=true` (`src/constants.ts:7-16`; `src/execute.ts:102-109`). The test suite verifies both readonly blocks and build-agent success (`index.test.ts:1169-1227`).

## Pitfalls and residual risks

- The plugin depends on a remote model to produce the merged file, so safety guards are essential but not a proof of semantic correctness. Import preservation is deliberately heuristic and parser support is regex-based across multiple languages (`src/imports.ts:1-8`, `65-75`); unusual syntax or multiline forms can escape detection.
- `resolveTargetPath` falls back to the lexically resolved path if `realpathSync` fails (`src/path-confinement.ts:81-94`, `115-121`). That is reasonable for transient filesystem errors but should be treated as a review point when extending confinement to hostile or highly concurrent filesystems.
- README and tool descriptions warn that omitting markers can delete surrounding code, and the API fallback is native `edit` (`impl.ts:259-280`; `README.md:167-201`). Consumers should preserve the documented distinction: Morph failure fallback is not the same as native-edit failure recovery.
- The checked clone could not run its tests without installing dependencies. CI is intended to provide the missing installation step (`.github/workflows/ci.yml:15-25`), but this local report has no passing runtime-test evidence.

## Transferable takeaways

1. Export exactly one OpenCode plugin factory from the entry module.
2. Separate tool execution from platform wiring and inject all external effects for deterministic tests.
3. Treat model-generated edits as untrusted output: confine paths, reject dangerous markers/truncation/import loss, scrub errors, and write only after validation.
4. Keep routing instructions canonical, packaged, and drift-tested across tool description, always-on instructions, and README.
5. Test release metadata and packaged-file inclusion, not only TypeScript behavior; frozen-lockfile CI and tag-note extraction make metadata drift operationally significant.
