## OpenCode Patterns

- The plugin uses the standard `PluginModule` shape: a default export with an ID and `server`, where the async plugin returns a `Hooks` object containing a tool (`src/index.ts:1-11`, `65-68`). This is a minimal, recognizable integration pattern for a single-purpose plugin.
- The exposed tool schema carries operational guidance in its description, including when not to use raster generation, how to label reference images, the one-image-per-call behavior, authentication prerequisites, and the absolute-path result contract (`src/index.ts:12-19`). Arguments are typed at the tool boundary for prompt, output path, quality enum, optional size, and optional reference paths (`src/index.ts:21-38`).
- Execution composes small role-specific helpers: load auth, read reference images, call the backend, then save output; the returned tool result includes human-readable output and structured metadata (`src/index.ts:40-59`). The metadata reports the saved path, whether versioning occurred, and subscription billing (`src/index.ts:49-57`).
- Relative paths are resolved against OpenCode's `ctx.directory`, while absolute paths are honored for both input and output (`src/input-image.ts:5-12`, `src/output-image.ts:44-53`). The README documents the same project-relative behavior and automatic plugin installation through OpenCode's config (`README.md:22-33`).
- The plugin mirrors OpenCode's auth precedence: `OPENCODE_AUTH_CONTENT` takes precedence over `$XDG_DATA_HOME/opencode/auth.json`, then accepts only an `openai` OAuth entry with a string access token (`src/auth.ts:6-24`). This avoids adding a separate credential store, matching the README's stated design (`README.md:73-75`).

## Security and Reliability

- The OAuth access token is inserted into an `Authorization: Bearer` header and sent to `https://chatgpt.com/backend-api/codex/responses`; an optional account ID is also forwarded (`src/codex.ts:7`, `73-82`). This is a high-impact trust boundary: the implementation depends on an internal/unstable ChatGPT backend contract rather than a documented public API, and the README correctly labels the project unofficial (`README.md:73-80`). A production plugin should document endpoint volatility and avoid logging the token or full request body.
- Reference image paths accept arbitrary absolute paths and `..` traversal from the context directory, then read and base64-encode the bytes (`src/input-image.ts:5-12`). Output paths have the same unrestricted absolute/traversal behavior and create parent directories recursively (`src/output-image.ts:40-48`). This is convenient for a local trusted agent, but it permits tool callers to read local image files and write anywhere the process can access; a constrained plugin should define an allowlisted workspace policy or require explicit consent for outside-workspace paths.
- MIME validation uses `file-type` content sniffing and rejects non-images, which is stronger than trusting extensions (`src/input-image.ts:7-12`). It still reads the entire file into memory and embeds it as a data URL, so large inputs can cause memory and request-size pressure (`src/input-image.ts:7-12`, `18-19`).
- Non-overwrite behavior is best effort only: existence is checked, then a separate write occurs, and the source explicitly acknowledges that a concurrent writer can win the race (`src/output-image.ts:16-27`, `40-48`). Atomic exclusive creation (`wx`) with retry would be safer. The bounded `-v2` through `-v999` policy prevents an unbounded search but returns an error after exhaustion (`src/output-image.ts:4`, `21-27`).
- The backend response parser ignores malformed/heartbeat events, requires the exact image-generation completion shape, rejects empty results, and fails if no usable result arrives (`src/codex.ts:18-40`). HTTP failures include status and at most 500 response characters (`src/codex.ts:84-86`), which improves diagnosis but may expose upstream response details to the agent.
- Auth loading deliberately swallows all read and parse errors and returns `undefined` (`src/auth.ts:19-30`). This prevents credential/path details from escaping, but collapses malformed auth, missing files, and filesystem failures into the same user-facing error (`src/index.ts:41-44`), making troubleshooting less precise.

## Testing Lessons

- The default test script is deliberately unit-only (`bun test tests/unit`), while the subscription e2e test has its own script and calls real `opencode` with a real authenticated environment (`package.json:17-24`; `tests/e2e/subscription.test.ts:16-27`, `40-67`). This separation avoids accidental paid/network tests in CI and makes the expensive boundary explicit.
- Unit tests cover auth precedence and validation, including malformed JSON and missing files (`tests/unit/auth.test.ts:50-93`); content-sniffed PNG/JPEG/GIF/WebP/BMP inputs, path resolution, ordering, unsupported files, and fail-fast missing references (`tests/unit/input-image.test.ts:18-80`); and output versioning, directory creation, absolute paths, decoded bytes, and exhaustion (`tests/unit/output-image.test.ts:24-114`).
- SSE tests assert ignored unrelated events, empty results, missing results, HTTP error formatting, exact endpoint/headers, optional-field omission, and the load-bearing forced tool choice (`tests/unit/codex.test.ts:23-71`, `74-143`). Testing the serialized request shape is especially valuable for a backend adapter.
- The e2e suite verifies actual PNG signatures and dimensions for generation, auto-versioning, and reference-image composition (`tests/e2e/subscription.test.ts:70-79`, `81-141`). It uses a temporary workdir/config and a ten-minute operation timeout (`tests/e2e/subscription.test.ts:9-13`), but the default CI path intentionally does not run it (`.github/workflows/_checks.yml:14-17`). A mocked integration contract would help cover the plugin entrypoint without credentials or generation cost.
- A local `bun test tests/unit` attempt at this snapshot was unavailable because dependencies were not installed: `xdg-basedir`, `file-type`, and `eventsource-parser/stream` could not be resolved. The clone worktree was clean before and after the attempt. CI's frozen install is the reproducible prerequisite (`.github/workflows/_checks.yml:10-17`).

## Packaging and Release

- Bun builds the TypeScript entrypoint into a self-contained ESM runtime artifact while leaving packages external; `prepublishOnly` rebuilds it, and the package exposes only the built entrypoint (`package.json:5-24`). Strict typechecking covers both source and tests, with bundler module resolution and no emitted declarations (`tsconfig.json:1-12`).
- CI uses a reusable check workflow with pinned checkout action, frozen lockfile installation, typecheck, Biome, and unit tests (`.github/workflows/_checks.yml:6-17`). The release workflow reuses those checks before publishing (`.github/workflows/release.yml:8-13`).
- Release tags are accepted only when their commit is reachable from `origin/main`; publishing uses npm provenance/OIDC permissions and the GitHub CLI creates release notes (`.github/workflows/release.yml:15-38`). This is a strong supply-chain pattern, though the workflow selects `bun-version: latest` (`.github/workflows/release.yml:29-31`), which can introduce toolchain drift.
- The local release script requires a clean, synchronized `main`, prints the commit range and compare URL, asks for confirmation, and creates a version commit/tag before the outer npm script pushes it (`scripts/prepare-release.sh:11-27`, `49-69`; `package.json:25-27`). Human diff review is a useful guard for a package that sends credentials and writes files.
- The repository's Bun install policy is configured as `minimumReleaseAge = 172800`, filtering packages newer than two days (`bunfig.toml:1-3`). This reduces exposure to just-published dependency compromises, but it should be aligned with the stated policy if a longer delay is intended.

## Practical Takeaways

- Reuse OpenCode's plugin factory and context directory, but keep tool descriptions explicit about capability boundaries and side effects (`src/index.ts:8-19`, `40-59`).
- Make credential precedence and serialized upstream requests directly testable; these tests catch compatibility regressions better than helper-only assertions (`tests/unit/auth.test.ts:50-93`, `tests/unit/codex.test.ts:80-133`).
- Treat local file access and output writes as security-sensitive tool capabilities. Add workspace containment, input size limits, output validation, and atomic exclusive creation before adapting this pattern for less-trusted agents.
- Keep costly authenticated e2e tests opt-in, while adding deterministic mocked plugin-level tests and pinning CI runtime versions for reproducibility (`package.json:22-24`, `.github/workflows/_checks.yml:11-17`).
