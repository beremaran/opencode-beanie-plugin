## Identity and scope

- Package: `crewbee` version `0.1.24`, MIT licensed, described as a “Team-first Agent System” (`package.json:1-8`). OpenCode is the first supported host and the product projects reusable Team assets into it (`README.md:11-23`, `README.md:95-119`).

## SDK and registration

- The plugin is typed against `@opencode-ai/plugin` and exports an async `Plugin` implementation (`src/adapters/opencode/plugin.ts:1`, `src/adapters/opencode/plugin.ts:18-18`). The package depends on `@opencode-ai/plugin` `1.15.10` (`package.json:52-59`).
- The published root entry dynamically imports the built module, selects `default` or the module itself, then re-exports `default`, `id`, and `server` (`opencode-plugin.mjs:1-7`). Package metadata points `main` and the export entries at `dist/opencode-plugin.mjs` (`package.json:14-21`).
- Initialization repairs/ensures the CrewBee config, loads and validates the Team library, bootstraps projected agents, starts background release refresh, and creates per-worktree delegation state (`src/adapters/opencode/plugin.ts:18-46`).
- The returned registration object uses `config`, `tool`, `event`, `chat.message`, `tool.definition`, `tool.execute.before`, `tool.execute.after`, `experimental.chat.system.transform`, and `experimental.session.compacting` (`src/adapters/opencode/plugin.ts:48-84`).
- The adapter declares native host agent/model selection and host CLI usage, while claiming safe co-installation with foreign plugins and a reserved config-key prefix (`src/adapters/opencode/bootstrap.ts:64-83`).

## Hooks, events, and context

- `config` rebuilds projections against the current config and provider/model registry, updates the in-memory boot and alias index, writes projected agents/default agent into the host config, and logs inserted/updated/skipped keys (`src/adapters/opencode/config-hook.ts:73-123`).
- `chat.message` resolves the selected or default projected agent, creates a session binding containing session/team/canonical-agent/mode/source, and checkpoints the selected model (`src/adapters/opencode/chat-message-hook.ts:28-60`).
- System transformation appends a compact runtime block containing Team, Entry Agent, Active Owner, and Mode; load warnings are also rendered into the system prompt (`src/adapters/opencode/system-transform-hook.ts:4-44`).
- Event handling maps `session.status` busy/idle to task running/completion, handles `session.idle`, `session.error`, `session.compacted`, and `session.deleted`, including cancellation and cleanup (`src/adapters/opencode/event-hook.ts:32-76`).
- `tool.execute.before` only rewrites `task` calls for sessions with a binding, translating `subagent_type` aliases to projected config keys (`src/adapters/opencode/tool-hooks.ts:80-99`). The after hook parses task results, adds resume/error guidance, and exposes session/task metadata (`src/adapters/opencode/tool-hooks.ts:101-125`).

## Tools and commands

- The README identifies three registered delegation tools: `task`, `delegate_status`, and `delegate_cancel` (`README.md:513-520`). Tool definitions receive session/message/agent/directory/worktree/abort context and can publish metadata (`src/adapters/opencode/delegation/tools.ts:15-29`).
- Delegation creates child sessions with `parentID`, stores the parent/agent binding, prompts the selected projected agent, extracts the assistant response, and returns structured completion data with resume support (`src/adapters/opencode/delegation/tools.ts:55-73`, `src/adapters/opencode/delegation/tools.ts:145-197`).
- Foreground and background modes are supported; `run_in_background: true` maps to background mode, otherwise the explicit mode or foreground is used (`src/adapters/opencode/delegation/tools.ts:89-95`). Background tasks are launched with `promptAsync` when available, otherwise `prompt`, and failures update persistent task status (`src/adapters/opencode/delegation/tools.ts:222-263`).
- Target resolution accepts canonical config keys or aliases but requires the source agent’s allowed-target list; self-delegation is separately rejected (`src/adapters/opencode/delegation/resolve-agent.ts:10-45`, `src/adapters/opencode/delegation/resolve-agent.ts:47-53`).
- CLI/package operations include setup, install, update, uninstall, doctor, version, local/registry packaging, simulator runs, and release dry-run (`package.json:29-50`; `README.md:695-736`).

## Auth and providers

- No provider credential or login/auth implementation was found in the inspected plugin path. CrewBee asks OpenCode for its configured provider/model registry via `client.config.providers()` and converts provider/model IDs into `provider/model` strings (`src/adapters/opencode/model-availability.ts:21-55`).
- The provider probe preserves the SDK receiver binding and has a 750 ms default timeout, returning `undefined` instead of blocking startup on an unavailable/slow registry (`src/adapters/opencode/model-availability.ts:25-40`). Tests explicitly cover both behaviors (`tests/opencode/model-availability.test.mjs:6-30`, `tests/opencode/model-availability.test.mjs:32-45`).
- Model policy is host-oriented: strict explicit models are kept, non-strict models may fall back, recommendations are filtered by the visible registry, and unknown registries omit `model` to use the OpenCode host default (`README.md:534-545`). Delegated non-strict model-not-found errors are retried once without a model (`src/adapters/opencode/delegation/tools.ts:164-186`).

## State and processes

- `DelegateStateStore` persists versioned tasks, sessions, checkpoints, todos, and continuity state as JSON under `<install-root>/runtime/<sha1(worktree)>.json`; it caches the parsed state in-process and writes synchronously (`src/adapters/opencode/delegation/store.ts:17-29`, `src/adapters/opencode/delegation/store.ts:31-36`, `src/adapters/opencode/delegation/store.ts:152-177`).
- Session identity checks prevent resuming a task from a different parent session or agent; missing/stale sessions are recreated (`src/adapters/opencode/delegation/tools.ts:109-143`).
- Compaction records a timestamp and resets the no-text-tail counter; deletion removes session and continuity state (`src/adapters/opencode/delegation/store.ts:127-149`).
- The plugin starts a background release refresh during initialization (`src/adapters/opencode/plugin.ts:34-46`).

## Configuration and projection

- User configuration defaults to `~/.config/opencode/crewbee.json`; built-in Teams use IDs, file Teams use `@...` paths relative to the OpenCode config root, and lower priority wins (`README.md:341-363`).
- The checked-in example enables `coding-team`, provides per-agent model overrides, and leaves general/template/Wukong Teams disabled (`templates/crewbee.json:1-53`).
- Team source of truth is `team.manifest.yaml`, `team.policy.yaml`, and agent Markdown; `TEAM.md` is human-facing documentation only (`README.md:441-457`). The template manifest defines mission, scope, leader, members, workflow, governance, runtime model settings, tags, and prompt projection (`templates/teams/template-team/team.manifest.yaml:1-132`).
- Prompt projection only accepts snake_case paths; camelCase and `projection_schema` are unsupported (`README.md:459-478`). Tests verify rejection of camelCase frontmatter and projection paths (`tests/opencode/prompt-projection.test.mjs:152-170`).
- Projection collision detection excludes managed CrewBee entries from foreign-collision inputs and filters colliding config keys before binding/default selection (`src/adapters/opencode/bootstrap.ts:155-180`, `src/adapters/opencode/bootstrap.ts:189-240`).
- Installer reads JSONC, creates parent directories, backs up existing config with a timestamped sibling file, canonicalizes CrewBee plugin references to `crewbee`, and can remove/restore entries (`src/install/opencode-config-file.ts:28-46`, `src/install/opencode-config-file.ts:49-80`, `src/install/opencode-config-file.ts:88-167`).

## Errors and security

- Blocking Team validation issues are thrown as one newline-joined error; all issues are also logged with level, file, code, path, scope, fixability, and suggestion metadata (`src/adapters/opencode/config-hook.ts:29-53`).
- Delegation returns actionable error codes and retry guidance for missing/unknown agents, invalid sessions, mode errors, and forbidden nested/self delegation (`src/adapters/opencode/tool-hooks.ts:9-33`).
- Permission mapping translates host/tool names, filters unavailable tools, denies `task` by default, and then allows only explicitly permitted target patterns (`src/adapters/opencode/permission-mapper.ts:24-39`, `src/adapters/opencode/permission-mapper.ts:63-79`).
- The template policy forbids fabricated evidence, unauthorized irreversible/external actions, and hidden uncertainty; it requires scope, factual, completeness, and evidence checks (`templates/teams/template-team/team.policy.yaml:12-44`).
- Important operational risk: the projection can set the default agent unconditionally to the selected projected default (`src/adapters/opencode/bootstrap.ts:182-187`, `src/adapters/opencode/config-hook.ts:103-107`). The repository’s tests also assert that host built-in agents are disabled and a foreign default agent is overwritten (`tests/opencode/plugin-task-alias.test.mjs:92-103`, `tests/opencode/plugin-task-alias.test.mjs:126-136`).
- Important permission risk: the test fixture expects broad `bash`, `edit`, and `todowrite` allow rules for Coding Team roles (`tests/opencode/plugin-task-alias.test.mjs:138-149`); consumers should review generated agent permissions rather than assume least privilege.
- Runtime state uses synchronous, non-atomic JSON writes and `JSON.parse` without corruption recovery (`src/adapters/opencode/delegation/store.ts:152-177`). A crash during write or concurrent writers could lose/corrupt state; this is a reusable hardening opportunity.

## Tests, package, and installation

- Build uses strict NodeNext TypeScript with declarations/source maps and emits to `dist` (`tsconfig.base.json:1-21`). Package build runs `tsc` then a separate OpenCode bundle step; tests build first and run Node’s test runner over `tests/**/*.test.mjs` (`package.json:29-50`).
- OpenCode tests cover canonical aliases/config keys, host-agent disabling, task tool preservation, provider registry behavior, delegation fallback, stale sessions, prompt projection, partial Team loading, and ordering (`tests/opencode/plugin-task-alias.test.mjs:42-160`, `tests/opencode/delegate-task.test.mjs:130-224`).
- Installation tests verify canonical package-name registration and the cache layout `packages/crewbee@latest/node_modules/crewbee/opencode-plugin.mjs` (`tests/install/plugin-entry.test.mjs:9-33`). CLI tests cover canonical/deprecated flags, setup dry-run with “No files changed”, and human/machine-readable validation diagnostics (`tests/cli/install.test.mjs:25-177`).
- User onboarding is intentionally `npx crewbee@latest setup --with-opencode`; documentation says setup writes the canonical `crewbee` plugin entry, runs doctor, and does not modify repository files (`README.md:267-283`).

## Pitfalls and reusable lessons

- Keep one canonical agent ID across projection, default selection, session binding, delegation, and display names; CrewBee documents this explicitly (`README.md:64-75`) and tests reject legacy display/config aliases (`tests/opencode/plugin-task-alias.test.mjs:76-90`).
- Bind session state at message time, not only startup, because host agent/model selection is session-specific (`src/adapters/opencode/chat-message-hook.ts:33-60`).
- Query host model availability with a timeout and preserve method receiver binding; both are easy integration failure modes and are directly regression-tested (`src/adapters/opencode/model-availability.ts:25-37`, `tests/opencode/model-availability.test.mjs:6-45`).
- Treat aliases as UX only: resolve them immediately to host config keys before execution, while enforcing per-agent allowed targets (`src/adapters/opencode/tool-hooks.ts:84-98`, `src/adapters/opencode/delegation/resolve-agent.ts:16-45`).
- Return structured delegation results with stable IDs, resume hints, metadata, and explicit error codes; this makes background work and recovery inspectable (`src/adapters/opencode/tool-hooks.ts:101-123`, `src/adapters/opencode/delegation/tools.ts:187-195`).
- Preserve host defaults as the fallback for unknown model registries and non-strict model failures rather than hard-coding provider assumptions (`README.md:536-545`).
- Separate human-facing `TEAM.md` from machine-authoritative manifest/policy/agent files, and validate schema/path conventions early (`README.md:441-478`, `templates/teams/template-team/TEAM.md:59-67`).

## Assessment

CrewBee is a substantial OpenCode adapter pattern: it uses the SDK’s lifecycle hooks and client to project a declarative Team asset model into native agents, then adds constrained delegation, session continuity, and installation/doctor tooling around that projection. The strongest reusable patterns are host-registry discovery with bounded timeouts, canonical identity resolution, per-session bindings, explicit delegation permissions, structured task results, and backup-aware config mutation. The main integration cautions are its deliberate ownership of the default agent and host built-ins, broad generated permissions in the sample Team, and synchronous unguarded runtime-state persistence.
