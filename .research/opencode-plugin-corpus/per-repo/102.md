## What it does

`opencode-research-papers` registers an AI-facing `research_papers` tool rather than a slash command (`README.md:10-12`). The plugin entrypoint returns the tool in the OpenCode plugin shape and passes package options into its factory (`src/index.ts:1-13`). The tool accepts a query, source, filter, result limit, date range, and strictness flag (`src/tools/research_papers.ts:27-37`). It routes to arXiv and/or OpenAlex, filters and annotates results, deduplicates, limits output, and appends source failure warnings (`src/tools/research_papers.ts:38-120`).

## OpenCode patterns worth reusing

- **Minimal plugin surface:** Keep the plugin entrypoint thin: import the SDK `Plugin` type, build a tool, and return it under `tool` (`src/index.ts:1-13`). This isolates registration from business logic.
- **SDK schema at the boundary:** The tool declares enum, numeric range, default, optional, and boolean constraints through `tool.schema` (`src/tools/research_papers.ts:30-36`). This is a useful pattern for making AI-callable arguments explicit before execution.
- **Configurable defaults:** Package options are optional and resolved with nullish defaults (`src/tools/research_papers.ts:23-25`); README documents tuple configuration and its defaults (`README.md:67-81`).
- **Graceful multi-provider execution:** When both sources are selected, `Promise.allSettled` preserves successful results while capturing an individual rejection (`src/tools/research_papers.ts:50-76`). Single-source branches use equivalent local catches (`src/tools/research_papers.ts:77-93`), and the result includes actionable warnings instead of crashing (`src/tools/research_papers.ts:145-180`).
- **External-call containment:** Both source adapters use `AbortController` and a 15-second timeout, check HTTP status, and convert failures to source-specific errors (`src/sources/arxiv.ts:4-18`, `src/sources/arxiv.ts:40-49`; `src/sources/openalex.ts:3-14`, `src/sources/openalex.ts:40-47`).
- **Respect upstream rate limits:** arXiv calls are serialized by a module-level 3.1-second cooldown (`src/tools/research_papers.ts:7-20`), matching the README's stated three-second spacing (`README.md:21-23`, `README.md:97-100`).
- **Normalize provider data:** Each adapter maps its native response to a shared `PaperResult` model (`src/types.ts:1-12`), including author/date/link/abstract/citation fields (`src/sources/arxiv.ts:68-81`, `src/sources/openalex.ts:50-64`). OpenAlex inverted-index abstracts are reconstructed in position order (`src/sources/openalex.ts:67-79`).
- **Stable, bounded presentation:** Output is deterministic markdown with source, filter, result count, optional evidence, links, and a 300-character abstract cap (`src/formatters/markdown.ts:15-64`). Authors are capped at three plus `et al.` (`src/formatters/markdown.ts:30-35`).

## Pitfalls and correctness risks

- **The documented routing is not really fallback-only.** README describes a primary and fallback for `auto` (`README.md:83-93`), but `resolveRouting` enables both sources for auto regardless of filter (`src/tools/research_papers.ts:132-143`), and the dual-source branch fetches both in parallel (`src/tools/research_papers.ts:50-64`). This increases traffic and rate-limit exposure; document it as aggregation or implement true primary-then-fallback semantics.
- **“Trending” is citation sorting.** OpenAlex maps both `top_cited` and `trending` to `cited_by_count:desc` (`src/sources/openalex.ts:16-24`), so the label does not represent temporal momentum. Tests lock in that behavior (`src/__tests__/openalex.test.ts:111-123`), making the mismatch easy to miss.
- **Date filtering has a JavaScript date trap.** The filter's `try/catch` does not catch an invalid date because `new Date(pub)` returns an invalid Date without throwing; such a record is then rejected by the comparison (`src/tools/research_papers.ts:250-263`). Unknown dates are intentionally retained, but malformed dates are silently dropped.
- **Strict matching is deliberately heuristic.** It splits on whitespace, uses only the first query term as the anchor, and requires 66% of terms for queries with three or more terms (`src/tools/research_papers.ts:288-323`). Punctuation, phrases, stemming, and synonyms beyond the small fixed map can reduce recall; the README appropriately calls future semantic filtering a roadmap item (`README.md:113-120`).
- **Deduplication can discard distinct papers.** It lowercases and removes every non-ASCII-alphanumeric character from titles (`src/tools/research_papers.ts:211-213`), then keeps the first provider's record (`src/tools/research_papers.ts:182-208`). Similar titles can collide, while meaningful Unicode distinctions are erased.
- **Markdown output is not escaped.** Query text and provider-controlled title, author, abstract, and URLs are interpolated directly into markdown (`src/formatters/markdown.ts:10-59`). A malicious or markup-heavy upstream value can alter the rendered tool response. Escape markdown-sensitive text and validate/sanitize displayed URLs if the client renders markdown.
- **Transport security is inconsistent.** The arXiv endpoint is hard-coded as `http://export.arxiv.org/api/query` (`src/sources/arxiv.ts:4`), unlike OpenAlex's HTTPS endpoint (`src/sources/openalex.ts:3`). Use HTTPS where supported to avoid query/result tampering and metadata leakage.
- **Module-global throttling is process-wide but not robust coordination.** `lastArxivRequest` is shared by calls in one process (`src/tools/research_papers.ts:7-20`), which is useful for a single runtime but does not coordinate across processes/instances and does not add retries or backoff after failures.
- **Configuration defaults are not independently validated.** `defaultMaxResults` and `defaultSource` are assigned directly from `PluginOptions` (`src/tools/research_papers.ts:23-25`), while the runtime schema constrains the tool argument (`src/tools/research_papers.ts:30-35`). Invalid package configuration can therefore become an invalid schema default or unexpected runtime behavior; validate options explicitly.
- **Unused API compatibility residue:** `buildWarnings` receives `normalizedSource` but never uses it (`src/tools/research_papers.ts:112-115`, `145-152`). The tool accepts `semantic_scholar` as a deprecated alias (`src/tools/research_papers.ts:32`, `127-129`), but the public `PluginOptions` and source types omit that alias (`src/types.ts:14-20`). Keep compatibility behavior and types aligned.

## Security lessons

- Prefer HTTPS for all upstream endpoints; the arXiv HTTP constant is the clearest actionable issue (`src/sources/arxiv.ts:4`).
- Treat API response fields as untrusted content. The parser sanitizes whitespace but not markdown/control syntax (`src/sources/arxiv.ts:127-129`; `src/formatters/markdown.ts:25-59`). Escaping at the final presentation boundary is the safer default.
- Timeouts prevent a hanging provider from holding the tool indefinitely (`src/sources/arxiv.ts:7-17`, `src/sources/openalex.ts:6-13`), while `Promise.allSettled` prevents one provider's exception from suppressing the other (`src/tools/research_papers.ts:50-76`). These controls should be retained when adding providers.
- The package declares no API keys or secrets and documents keyless upstream access (`README.md:14-17`). The repository ignore rules also exclude `.env` and common dependency/build artifacts (`.gitignore:41-42`, `.gitignore:68-71`, `.gitignore:77-83`).

## Testing lessons and gaps

- Unit tests cover title normalization and merge ordering/deduplication, including case and punctuation variants (`src/__tests__/research_papers.test.ts:19-39`, `41-99`).
- Adapter tests use mocked `fetch` and verify URL construction, sorting, headers, HTTP error messages, XML/JSON parsing, empty input, author handling, and abstract reconstruction (`src/__tests__/arxiv.test.ts:39-141`, `src/__tests__/openalex.test.ts:29-142`). This keeps tests deterministic and avoids live API dependency.
- Formatter tests cover empty states, metadata, matched evidence, optional fields, truncation, author limits, and numbering (`src/__tests__/markdown.test.ts:15-157`).
- There is no visible end-to-end test of the registered tool factory/execution path, routing matrix, `Promise.allSettled` degradation, cooldown timing, date filtering, strict filtering, warning composition, or option validation. Add focused tests for those branches, especially malformed dates, both-provider failure, one-provider success, markdown escaping, and the semantic-scholar alias.
- CI runs typecheck, tests, and build after `npm ci` on Node 22 (`.github/workflows/ci.yml:8-30`). TypeScript excludes tests from the production compilation but enables strict mode and declarations (`tsconfig.json:1-18`), so the separate test command is important.

## Packaging and release lessons

- The package is ESM (`type: module`), publishes only `dist`, and exposes compiled JS plus declarations (`package.json:5-10`). `prepublishOnly` builds before publication (`package.json:11-17`); this keeps the npm payload narrow but means a missing build blocks publication.
- Runtime dependencies are minimal: the OpenCode SDK and `fast-xml-parser`; testing and semantic-release tooling remain development dependencies (`package.json:37-51`). The lockfile is committed and CI uses `npm ci` (`package.json:37-51`, `.github/workflows/ci.yml:20-21`).
- Release automation gates semantic-release behind the same typecheck/test/build CI and uses a full-history checkout with `persist-credentials: false` (`.github/workflows/release.yml:13-46`). Publishing uses npm registry setup, `GITHUB_TOKEN`, and `NPM_TOKEN` (`.github/workflows/release.yml:48-65`).
- Semantic-release updates `package.json` and `package-lock.json` through `@semantic-release/git`, publishes npm, and creates GitHub release metadata (`.releaserc.json:15-30`). The explicit `[skip ci]` release commit avoids recursive release runs (`.releaserc.json:23-27`).
- README documents OpenCode cache invalidation after updates (`README.md:39-53`), an operational detail that is easy to omit from plugin packaging guidance.

## Bottom line

This is a clean, small reference for an OpenCode tool plugin: thin registration, schema-defined inputs, isolated adapters, bounded external calls, partial-failure handling, normalized data, and deterministic formatting. Before treating it as production-hardened, fix the HTTP arXiv endpoint and markdown escaping, clarify auto routing/trending semantics, validate plugin options, and add execution-path tests around routing, failures, filtering, throttling, and malformed provider data.
