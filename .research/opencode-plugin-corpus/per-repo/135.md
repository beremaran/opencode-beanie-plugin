## OpenCode patterns

- The entrypoint is a named async export, `NotificationPlugin`, receiving the OpenCode context `{ project, client, $, directory, worktree }` ([notificator.js:69-70](../repos/panta82--opencode-notificator/notificator.js#L69-L70)). This is a minimal pattern for registering event and permission hooks without wrapping the plugin in a class.
- The returned hook object uses `event` for lifecycle events and `permission.ask` for permission requests ([notificator.js:129-146](../repos/panta82--opencode-notificator/notificator.js#L129-L146)). A `session.created` event records the session identifier, and only a matching `session.idle` produces the completion notification ([notificator.js:130-141](../repos/panta82--opencode-notificator/notificator.js#L130-L141)).
- Event-shape tolerance is handled by checking `event.sessionID`, `event.properties.sessionID`, and `event.properties.info.id` ([notificator.js:59-67](../repos/panta82--opencode-notificator/notificator.js#L59-L67)). This is a useful defensive pattern when event payload versions or sources differ.
- The plugin uses the SDK shell helper `$` with interpolated arguments for platform commands rather than manually spawning processes ([notificator.js:99-105](../repos/panta82--opencode-notificator/notificator.js#L99-L105), [notificator.js:117-123](../repos/panta82--opencode-notificator/notificator.js#L117-L123)). macOS uses `afplay` and `osascript`; Linux uses `ffplay` and `notify-send`.
- Configuration is colocated with the bundled plugin. The loader reads `notificator.jsonc` relative to the module, strips line/block comments, and falls back to `{}` after logging a parse/read failure ([notificator.js:8-23](../repos/panta82--opencode-notificator/notificator.js#L8-L23)). Defaults are expressed as negative checks, so absent `enabled` fields leave notifications enabled ([notificator.js:70-75](../repos/panta82--opencode-notificator/notificator.js#L70-L75)).
- Sound selection is deterministic: supported audio extensions are filtered and sorted, then a simple hash of project path plus seed selects a file ([notificator.js:37-55](../repos/panta82--opencode-notificator/notificator.js#L37-L55)). This gives per-project consistency while allowing an explicit file or configurable seed ([notificator.js:81-91](../repos/panta82--opencode-notificator/notificator.js#L81-L91)).

## Security and correctness pitfalls

- **High: macOS notification text is not safely escaped.** `sendNotification` only replaces apostrophes, then inserts event-derived `message` and `title` inside a double-quoted AppleScript string ([notificator.js:117-120](../repos/panta82--opencode-notificator/notificator.js#L117-L120)). Permission text includes `input.type` ([notificator.js:142-145](../repos/panta82--opencode-notificator/notificator.js#L142-L145)); a value containing double quotes or AppleScript syntax can break the script and, depending on shell-helper semantics and AppleScript parsing, create an injection boundary. Encode AppleScript string literals or pass data through a safe mechanism.
- **Medium: platform claims are inconsistent.** README advertises macOS and Linux support ([README.md:49-59](../repos/panta82--opencode-notificator/README.md#L49-L59)), while the agent guidance says to support Windows too ([AGENTS.md:29-33](../repos/panta82--opencode-notificator/AGENTS.md#L29-L33)); however, the implementation has branches only for `darwin` and `linux`, with no Windows notification/audio path ([notificator.js:97-105](../repos/panta82--opencode-notificator/notificator.js#L97-L105), [notificator.js:114-123](../repos/panta82--opencode-notificator/notificator.js#L114-L123)). Either implement Windows or remove the claim and add an explicit unsupported-platform behavior.
- **Medium: session state is process-global.** `currentSessionID` is a module-level variable ([notificator.js:57-57](../repos/panta82--opencode-notificator/notificator.js#L57-L57)). Multiple plugin instances/projects in one process can overwrite it, causing a later idle event to be ignored or associated with the wrong project. State should be scoped to the plugin instance or keyed by project/session.
- **Medium: explicit sound paths are not constrained to the asset directory.** `soundConfig.file` is accepted verbatim and joined with the sounds directory ([notificator.js:81-84](../repos/panta82--opencode-notificator/notificator.js#L81-L84), [notificator.js:93-97](../repos/panta82--opencode-notificator/notificator.js#L93-L97)). Because configuration is local, this is primarily a local-trust boundary, but basename validation or a resolved-path containment check would prevent accidental or malicious path traversal.
- **Low: configuration parsing is regex-based.** Removing `//` comments before JSON parsing can corrupt valid string values containing `//`, and the parser does not handle all JSONC edge cases ([notificator.js:8-19](../repos/panta82--opencode-notificator/notificator.js#L8-L19)). A JSONC parser or a narrower parser would make failure behavior predictable.
- **Low: unknown platforms silently do nothing.** The notification/audio functions have no `else` branch for unsupported platforms, and audio errors are deliberately swallowed ([notificator.js:99-109](../repos/panta82--opencode-notificator/notificator.js#L99-L109)). This avoids disrupting OpenCode but makes misconfiguration difficult to diagnose.

## Testing lessons

- There is no `test` script in `package.json`; only build and deployment scripts are defined ([package.json:7-12](../repos/panta82--opencode-notificator/package.json#L7-L12)). No test files are present in the clone, and `AGENTS.md` describes manual testing by copying files and triggering generation/permission events ([AGENTS.md:20-27](../repos/panta82--opencode-notificator/AGENTS.md#L20-L27)).
- The manual test plan should be supplemented with unit tests for JSONC loading, volume clamping, sound rotation, event-session matching, and every supported event payload shape. Platform adapters should be injectable so command construction and escaping can be tested without desktop audio/notification binaries.
- Regression coverage is especially important for macOS escaping, multiple simultaneous plugin instances, missing sound directories, invalid config, and unsupported platforms. The current fallback behavior is visible in source but not mechanically verified ([notificator.js:20-23](../repos/panta82--opencode-notificator/notificator.js#L20-L23), [notificator.js:43-46](../repos/panta82--opencode-notificator/notificator.js#L43-L46)).

## Packaging and release lessons

- `package.json` declares ESM, the plugin entrypoint, the SDK dependency, and esbuild dev dependency ([package.json:2-26](../repos/panta82--opencode-notificator/package.json#L2-L26)); the lockfile records the same direct dependency set with lockfile version 3 ([package-lock.json:1-17](../repos/panta82--opencode-notificator/package-lock.json#L1-L17)).
- The build bundles `notificator.js` for Node 18 ESM while externalizing `@opencode-ai/plugin`, emits a sourcemap, and copies both the sound directory and JSONC config into `dist/` ([build.js:19-39](../repos/panta82--opencode-notificator/build.js#L19-L39)). This is a clear separation between source dependencies and the runtime plugin payload.
- Deployment maps Linux and macOS to `~/.config/opencode/plugin` and Windows to the roaming AppData equivalent ([deploy.js:8-18](../repos/panta82--opencode-notificator/deploy.js#L8-L18)). It removes existing destination files/directories before copying, but intentionally preserves an existing `notificator.jsonc` ([deploy.js:61-85](../repos/panta82--opencode-notificator/deploy.js#L61-L85)). Preserving user configuration is a good upgrade property; the destructive replacement of other destination entries warrants careful path validation and a dry-run/backup option for production tooling.
- The deploy script shells out to `npm run build` via `execSync` ([deploy.js:39-47](../repos/panta82--opencode-notificator/deploy.js#L39-L47)), so the documented npm workflow is part of the packaging contract. The repository ignores `dist/` and `node_modules/`, leaving generated artifacts out of version control ([.gitignore:1-4](../repos/panta82--opencode-notificator/.gitignore#L1-L4)).
- README says deployment overwrites an existing version ([README.md:27-35](../repos/panta82--opencode-notificator/README.md#L27-L35)), but does not call out that the config file is preserved. Documenting that exception would reduce surprise during upgrades.

## Bottom line

This repository demonstrates a compact OpenCode plugin pattern: export one async plugin factory, return named lifecycle/permission hooks, use the SDK shell helper for OS integration, and package code plus non-code assets together. Its strongest practical ideas are deterministic per-project sound selection, tolerant event-ID extraction, and preservation of user configuration during deployment. The main follow-ups are to add automated tests, make macOS text encoding safe, scope session state correctly, and reconcile or implement Windows support before treating the plugin as cross-platform.
