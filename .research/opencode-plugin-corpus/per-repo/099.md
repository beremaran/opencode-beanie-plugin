## What it does

Pocket Universe is a WIP orchestration plugin that adds asynchronous sibling-agent spawning, inter-agent messaging, recall/history, automatic resumption, and optional per-agent git worktrees. The README explicitly describes three tools, `broadcast`, `subagent`, and `recall` (`README.md:3-13`), and documents a dependency on upstream OpenCode changes for async subagents, resumption, main-session blocking, and subagent-only tool scoping (`README.md:27-29`).

The entrypoint stores the SDK client and combines hook and registry contributions into the exported `Plugin` object (`src/index.ts:12-25`). The registry conditionally registers the three tools based on configuration (`src/plugin/registry.ts:7-16`) and intercepts `/pocket` before normal command execution by clearing command parts before handling the command itself (`src/plugin/registry.ts:18-52`).

## OpenCode patterns worth reusing

### Plugin composition and tool registration

- Use the official `tool()` helper and schema builders for tool descriptions and argument validation (`src/tools/broadcast.ts:5-46`, `src/tools/subagent.ts:141-155`, `src/tools/recall.ts:11-24`).
- Return hook names and registries from small factory functions, then spread them from the plugin entrypoint. This keeps the plugin entrypoint thin and makes the feature surface discoverable (`src/index.ts:19-22`, `src/plugin/hooks.ts:62-66`).
- Use `config` transformation to register commands and add enabled tools to `experimental.subagent_tools` (`src/plugin/registry.ts:54-85`). This is a useful pattern when a plugin needs tools scoped to subagents, but it should avoid injecting unrelated global paths; see pitfalls below.
- Detect child sessions through the session API before adding orchestration behavior. The system and message transforms skip the main session and operate on child sessions (`src/plugin/hooks.ts:489-507`, `src/plugin/hooks.ts:689-711`).

### Lifecycle-aware message delivery

- The plugin uses `experimental.chat.system.transform` for dynamic instructions and `experimental.chat.messages.transform` for synthetic inbox/task messages (`src/plugin/hooks.ts:489-637`, `src/plugin/hooks.ts:639-767`). Placing inbox data at the end of the message list is an explicit recency-bias choice (`src/plugin/hooks.ts:765-766`).
- A useful delivery invariant is tracked explicitly: messages are marked presented when injected, and only unhandled, unpresented messages trigger resumption (`src/messaging/core.ts:62-76`, `src/messaging/core.ts:99-112`). This prevents duplicate wakeups.
- `session.before.idle` waits for pending descendants, then uses `resumePrompt` for unread messages or deferred subagent output (`src/plugin/hooks.ts:115-217`, `src/plugin/hooks.ts:220-251`). The loop has both a 100-iteration cap and five-minute per-session polling timeout (`src/plugin/hooks.ts:82-112`, `src/plugin/hooks.ts:115-120`). These are pragmatic safeguards for asynchronous orchestration.
- For an active caller, subagent output can be persisted with `noReply: true`; for idle or hook-waiting callers it is retained for the idle hook to consume (`src/messaging/resume.ts:144-190`, `src/messaging/resume.ts:193-261`). The distinction is a good model for avoiding mid-turn prompt races.

### State isolation and bounded memory

- Agent aliases, messages, histories, and session states are scoped by root session, preventing agents from separate main sessions being listed or messaged together (`src/messaging/core.ts:114-161`, `src/state.ts:174-217`).
- In-memory inboxes have TTLs, a maximum size, and a periodic cleanup task (`src/state.ts:25-37`, `src/state.ts:532-588`). Message queues also evict handled messages first when full (`src/messaging/core.ts:33-45`).
- The subagent list is cached for five minutes and concurrent fetches share one in-flight promise (`src/agents.ts:8-12`, `src/agents.ts:42-85`). This avoids repeated `/agent` calls during system-prompt construction and spawning.
- Subagent spawning inherits the caller's latest user-message agent/model metadata, validates requested agent types, and records virtual depth (`src/tools/subagent.ts:63-135`, `src/tools/subagent.ts:172-206`). The resulting session is created as a sibling using the caller's parent (`src/tools/subagent.ts:215-240`).

### Configuration and worktree options

- Local `.pocket-universe.jsonc` takes precedence over a global OpenCode config, and nested values are merged with defaults (`src/config.ts:135-137`, `src/config.ts:237-249`, `src/config.ts:274-313`). This is a practical configuration UX for project-specific behavior.
- Optional worktrees are created detached from `HEAD`, with the path surfaced in the injected agent instructions (`src/worktree.ts:41-79`, `src/plugin/hooks.ts:515-525`, `src/prompts/system.ts:98-105`). The README clearly says worktrees are disabled by default and preserved for manual review (`README.md:21-24`, `README.md:271-279`).
- The system prompt is conditionally rendered from feature flags and includes a max-depth warning instead of advertising unavailable tools (`src/prompts/system.ts:32-67`, `src/prompts/system.ts:169-195`).

## Pitfalls and risks

### High: likely TypeScript build failure

`createSubagentTool().execute` declares `const callerModelInfo` once before agent selection (`src/tools/subagent.ts:187-206`) and declares another `const callerModelInfo` in the same function block before launching the prompt (`src/tools/subagent.ts:315-340`). In TypeScript/JavaScript lexical scope, this duplicate declaration should fail compilation. The second declaration is also redundant because the first value is still available. This is especially important because the package's build and typecheck scripts run TypeScript (`package.json:18-21`).

### High: configuration transform adds an unrelated hard-coded path

Every config transformation appends `~/.config/opencode/plugin-test-skill` to `input.skills.paths` (`src/plugin/registry.ts:64-68`). This path is not configurable, is not part of the package, and is not documented in the README configuration section (`README.md:154-225`). It can make consumers load a missing or unintended skill directory and creates hidden environment coupling. A production plugin should either remove this registration or expose a documented, validated option.

### Medium: JSONC parser can corrupt valid strings

The custom parser strips `//` comments with a regular expression before parsing JSON (`src/config.ts:216-234`). A URL or string value containing `//` can therefore be truncated or changed. Prefer a JSONC parser or a lexer that understands quoted strings. The broad catch then silently falls back to defaults (`src/config.ts:297-313`), making this failure difficult for users to diagnose.

### Medium: process-global mutable state limits isolation

The plugin stores clients, aliases, inboxes, histories, and session state in module-level maps/sets (`src/state.ts:253-336`, `src/state.ts:434-463`, `src/state.ts:514-518`). Cleanup clears many stores but deliberately retains some state such as completed history, cleaned-up sessions, and summary markers (`src/state.ts:766-805`). This can work for one OpenCode process, but concurrent plugin instances, hot reloads, or multiple clients need explicit lifecycle ownership and tests for cross-session leakage.

### Medium: unsafe and destructive worktree command construction

Worktree paths are interpolated into shell command strings, even though they are double-quoted (`src/worktree.ts:62-75`, `src/worktree.ts:93-118`). Alias generation is currently constrained to letters and digits (`src/state.ts:599-609`), which reduces exposure, but the helper accepts arbitrary `alias` and `cwd` inputs. Prefer argument-array process execution or strict path validation. The implementation also force-removes an existing worktree before recreating it (`src/worktree.ts:62-70`), which is destructive if a stale-path check is wrong.

### Medium: sensitive data may be written to logs

When enabled, the logger serializes arbitrary data and writes it to `.logs/pocket-universe.log` (`src/logger.ts:82-93`). Call sites include message previews, task descriptions, model/provider IDs, and error strings (`src/messaging/session-update.ts:137-177`, `src/tools/subagent.ts:318-349`). Logging is disabled by default, but there is no redaction or size policy beyond some message truncation in the broadcast tool (`src/tools/broadcast.ts:69-78`). Treat debug logging as potentially sensitive and redact prompt/output content.

### Medium: internal SDK assumptions are weakly typed

The plugin casts `ctx.client` to a custom client interface (`src/index.ts:12-17`) and accesses internal `_client`/`client` objects for `/agent` and parent notifications (`src/agents.ts:14-24`, `src/tools/broadcast.ts:250-270`). It also casts bodies to include fields absent from the minimal interface, such as `noReply`, `ignored`, and `hideQueueBadge` (`src/messaging/session-update.ts:143-161`, `src/messaging/resume.ts:210-223`). These assumptions need version-gated adapters or integration tests against the supported OpenCode SDK versions.

## Testing lessons

- No test files are present in the clone inventory, and `package.json` has no `test` script (`package.json:18-21`). The repository therefore lacks automated coverage for its most failure-prone behavior: idle-hook races, duplicate delivery, cleanup, cross-root isolation, command routing, and model inheritance.
- Add unit tests around pure boundaries first: JSONC parsing/merging (`src/config.ts:216-234`), alias/root scoping (`src/state.ts:599-665`), inbox TTL/eviction (`src/state.ts:532-572`, `src/messaging/core.ts:22-55`), and `/pocket` validation (`src/commands/pocket.ts:102-183`).
- Add mocked SDK integration tests for `session.before.idle`, `session.idle`, `messages.transform`, and asynchronous subagent completion (`src/plugin/hooks.ts:68-341`, `src/tools/subagent.ts:333-475`). Explicitly test the active, idle, and in-hook output-delivery branches (`src/messaging/resume.ts:160-261`).
- Add a compile gate that catches duplicate declarations and checks the generated declaration files. The current scripts provide `typecheck` and a prepublish build, but there is no test or package smoke check (`package.json:18-21`).

## Packaging and release lessons

- The package uses ESM, exposes `dist/index.js` and `dist/index.d.ts`, externalizes `@opencode-ai/plugin`, and publishes only `dist` plus `README.md` (`package.json:4-16`, `package.json:18-21`). This is a sensible small plugin distribution shape.
- `@opencode-ai/plugin` is both a peer dependency (`^1.0.0`) and a dev dependency (`^1.0.143`), which is appropriate for host-provided runtime integration but should be paired with an explicit compatibility policy because the README requires unreleased upstream behavior (`package.json:31-39`, `README.md:27-29`).
- The lockfile workspace name is `@opencode-ai/plugin-inbox`, not the package name `@spoons-and-mirrors/pocket-universe` (`bun.lock:4-8`, `package.json:1-3`). This suggests a rename was not propagated and can confuse reproducibility or release tooling.
- `.npmignore` excludes TypeScript sources and `.opencode`, while `files` includes only build output and README (`.npmignore:1-17`, `package.json:14-16`). Before publishing, verify that generated declaration maps are intentionally included and that no required runtime assets are omitted.
- The README labels the project WIP and says installation is simply adding the package to the OpenCode plugin array (`README.md:1-5`, `README.md:31-37`). Release documentation should additionally state the supported OpenCode version/commit, required upstream PRs, configuration file creation behavior, and whether worktree force-removal is expected.

## Bottom line

The strongest reusable design is the lifecycle-aware delivery model: scoped session state, synthetic transform messages, explicit presented/handled tracking, and hook-level resumption. The plugin also demonstrates good operational safeguards through bounded queues, TTL cleanup, configurable depth, and opt-in worktrees. It is not release-ready as inspected: the duplicate lexical declaration likely blocks the TypeScript build, the config hook injects an unrelated hard-coded skill path, there are no tests, and packaging metadata contains a stale lockfile name. Fix those issues and add mocked lifecycle tests before relying on the orchestration guarantees documented in the README.
