## What it does

- The plugin registers a single native tool named `google_ai_search_plus` through `Tool.define`, with `query`, bounded `timeout`, and `followUp` parameters (`src/index.ts:12-30`). It returns formatted markdown and metadata through the OpenCode tool result and `ctx.metadata` (`src/index.ts:40-62`).
- The README positions it as a Google AI Mode/SGE scraper that uses Playwright and Turndown to produce webfetch-like markdown, including headings, lists, tables, and sources (`README.md:1-11`).
- Each tool execution creates a new `GoogleAIModeManager`; the manager owns a browser/page and disposes them in `finally`, while the abort listener also requests disposal (`src/index.ts:30-41`, `src/index.ts:63-72`).
- The browser navigates to Google Search with `udm=50`, `aep=22`, `q`, and `hl=en` query parameters, waits for network idle, then polls body text until it is stable (`src/index.ts:163-171`, `src/index.ts:174-207`).
- Extraction is selector- and class-name-driven. It finds a root using several Google-specific selectors, walks headings/lists/tables/paragraphs, separately parses source cards, and falls back to body text when structured output is short (`src/index.ts:249-267`, `src/index.ts:369-425`, `src/index.ts:497-541`).

## OpenCode patterns worth reusing

- **Native tool registration:** Define the tool inside the plugin callback so the host-provided `Tool` and `z` objects are used, then register it from `tool.register` (`src/index.ts:12-15`, `src/index.ts:76-80`).
- **Schema-level input bounds:** The timeout is constrained to 5-120 seconds at the schema boundary and clamped again before navigation (`src/index.ts:18-27`, `src/index.ts:31-34`). This is a useful defense against unbounded browser work.
- **Lifecycle and cancellation hooks:** Attach an abort listener to the OpenCode execution context, remove it in `finally`, and close page/browser resources in an idempotent-looking cleanup path (`src/index.ts:35-38`, `src/index.ts:69-72`, `src/index.ts:578-588`).
- **Metadata for model/UI consumers:** The result exposes query, response time, source information, and table presence rather than returning only a string (`src/index.ts:43-61`).
- **Graceful optional dependency failure:** Playwright is dynamically imported and the error explains both the package and browser installation commands (`src/index.ts:83-95`). The package correspondingly declares Playwright as a peer dependency and Turndown as a runtime dependency (`package.json:21-30`).
- **Explicit distribution contract:** `main` and `types` point at `dist`, while TypeScript emits declarations and source maps (`package.json:5-10`, `tsconfig.json:8-13`). The README gives both local `file:///` and npm installation examples (`README.md:34-58`).

## Pitfalls and reliability risks

- **Brittle upstream DOM coupling:** The parser depends on Google class names such as `.mZJni`, `.Dn7Fzd`, `.Zkbeff`, `.Y3BBE`, `.Fv6NCb`, and `.ofHStc`, plus `data-*` attributes (`src/index.ts:249-259`, `src/index.ts:369-380`). Google markup changes can silently produce incomplete or fallback output. Tests should fixture representative DOM variants and assert extraction failure when required content disappears.
- **Timing is expensive and imprecise:** A network-idle navigation is followed by a fixed three-second delay and a two-second polling loop requiring three equal text lengths (`src/index.ts:180-207`). This can delay short answers, miss content that changes without changing length, and consume the full timeout while Google remains interactive. Prefer a selector/content readiness condition with a bounded stability window and record which condition ended the wait.
- **Abort is not propagated to Playwright operations:** The abort signal is checked only after parsing; `goto`, waits, and the polling loop do not receive or frequently check it (`src/index.ts:174-229`). Disposal from the event handler may race with those operations. Cancellation tests should abort during navigation, polling, and extraction and verify prompt completion without unhandled errors.
- **Session reuse is effectively absent:** The manager is instantiated per execution and always disposed in `finally`, despite the `followUp` parameter and session fields (`src/index.ts:30-33`, `src/index.ts:98-105`, `src/index.ts:114-119`, `src/index.ts:578-588`). `followUp` therefore cannot preserve a conversation across tool calls. Either make manager state truly shared with explicit isolation/expiry, or remove the advertised follow-up behavior.
- **Conversation metadata is incorrect:** `conversationIndex` is derived from a boolean and therefore reports `2` whenever the conversation is active, not an incrementing query count (`src/index.ts:555-560`). This is misleading telemetry and should be covered by a multi-query test if session reuse is implemented.
- **Selector classification appears inconsistent:** The code checks `node.classList.contains("otQkpb")` for headings, but the selector list does not include `.otQkpb`; it separately includes generic heading elements (`src/index.ts:258-286`). This may be harmless for semantic headings but is a sign that scraper selectors need focused fixtures and maintenance documentation.
- **Fallback and markdown paths can duplicate or leak page content:** Turndown converts the whole selected container’s raw HTML (`src/index.ts:354-355`, `src/index.ts:510-523`), while structured/fallback content is appended based on length heuristics (`src/index.ts:497-541`). Unrelated UI text not removed by the small tag blacklist can enter the answer, and the same content can be represented twice.
- **Error classification is overly broad and message-dependent:** Any error whose message contains `Timeout` or `forSelector` is rewritten as automated blocking, hiding genuine selector, network, or infrastructure failures (`src/index.ts:63-68`). Use typed errors or explicit block detection and preserve the original cause for diagnostics.
- **Google consent handling does not solve consent:** The parser detects consent phrases, but the branch merely chooses formatted/raw text instead of accepting or rejecting the consent page (`src/index.ts:361-367`, `src/index.ts:506-508`). A consent page can therefore be returned as if it were an answer.
- **Browser configuration weakens automation defenses:** Chromium is launched with `--no-sandbox`, and the plugin changes `navigator.webdriver`, removes a Chrome runtime property, and spoofs the user agent/languages (`src/index.ts:122-153`). These are operationally fragile and expand the security review surface; `--no-sandbox` is especially risky outside a separately isolated container. The README also openly describes stealth headers and automated access (`README.md:3`, `README.md:8`).
- **The hard-coded `/tmp` import is unsafe as a packaging convention:** If the normal Playwright import fails, the plugin imports `/tmp/node_modules/playwright` (`src/index.ts:83-90`). This is machine-specific and can load an unexpected dependency tree; a documented host dependency or standard resolver is safer.
- **Untrusted page text is interpolated into markdown links:** Extracted titles and URLs are inserted into `[title](url)` without URL scheme validation or escaping (`src/index.ts:627-633`). Although the source is Google-rendered content, this can create misleading markdown or unsafe link schemes if a result is manipulated. Restrict URLs to expected schemes and escape link labels.
- **Query text is placed into the tool title and output:** The query is interpolated into metadata/title and the response header without length limits or markdown escaping (`src/index.ts:43-55`, `src/index.ts:591-598`). Add a practical input limit and escape or delimit user-controlled text in markdown/UI-facing fields.

## Security lessons

- Treat browser automation as a privileged network client: the plugin sends arbitrary user queries to Google and parses remote HTML in a headless browser (`src/index.ts:174-186`, `src/index.ts:235-425`). Define allowed destinations, avoid carrying ambient credentials, and consider a browser sandbox rather than disabling it.
- Do not assume DOM-derived URLs are safe merely because they came from a search page. Validate schemes and normalize/escape link text before returning markdown (`src/index.ts:384-403`, `src/index.ts:627-633`).
- Keep failure details distinguishable. Replacing many operational failures with a generic anti-bot error makes incident diagnosis and abuse detection harder (`src/index.ts:63-68`).
- The plugin claims no persistent state, which limits cross-call leakage, but this follows from per-call disposal rather than an explicit security boundary (`README.md:78-82`, `src/index.ts:30-33`, `src/index.ts:69-72`). If reuse is added, key sessions to the OpenCode session/user and enforce expiry and cleanup.

## Testing lessons

- There is no test script or test directory in `package.json` or the clone inventory; the only scripts are build and clean (`package.json:8-11`). The README documents build/install steps but no automated verification (`README.md:85-89`).
- Add unit tests for timeout schema behavior, default/clamped timeout calculation, abort handling, error classification, source deduplication, table truncation, markdown escaping, consent detection, and fallback selection (`src/index.ts:17-34`, `src/index.ts:63-72`, `src/index.ts:369-425`, `src/index.ts:497-541`, `src/index.ts:627-633`).
- Add DOM-fixture tests for each root/container selector and for Google response variants, including no structured blocks, changing text with equal lengths, consent pages, source cards without links, tables with missing cells, and malformed HTML (`src/index.ts:249-425`).
- Add an integration test with a mocked Playwright module or controlled browser page to prove disposal after success, timeout, thrown navigation error, and abort. Browser tests should not depend on live Google because the README warns that automated traffic is frequently throttled or blocked (`README.md:78-81`).
- Run `bun run build` in CI. Strict TypeScript is enabled, but the implementation uses `any` for tool parameters and extracted blocks, which weakens compile-time protection (`tsconfig.json:8-16`, `src/index.ts:30`, `src/index.ts:264`, `src/index.ts:432`).

## Packaging and configuration lessons

- The package is ESM and points consumers to `dist/index.js` plus generated declarations (`package.json:2-10`). This is a clean minimal contract, but there is no `files` allowlist, repository URL, publish config, or versioned dependency range (`package.json:1-31`). Verify the npm tarball contains the built entrypoint and README, and prefer tested version ranges over `latest` for runtime reproducibility (`package.json:21-30`).
- Playwright is a peer dependency because the host must install the browser package and Chromium separately (`package.json:24-30`, `README.md:25-32`). Installation should fail with a clear, actionable message, as this implementation does (`src/index.ts:90-93`), but the documented `npx` command conflicts with the repository guidance to use Bun and may produce a different package-manager lock state (`README.md:25-32`).
- The `.gitignore` excludes `dist/`, local `opencode.json`, dependencies, coverage, and temporary files (`.gitignore:1-10`, `.gitignore:33-38`). Excluding local config is appropriate, but publish/CI instructions should make clear that consumers configure the plugin in their own OpenCode project (`README.md:34-46`).
- The README explicitly warns that source quote escaping may need manual fixes (`README.md:23-23`), which is a release-quality warning that should instead be eliminated by CI build verification.

## Bottom line

This is a compact example of OpenCode-native tool registration, schema validation, context metadata, optional dependency loading, and cleanup. Its main lesson is that a scraper plugin needs stronger boundaries than its happy path shows: typed and cancellable browser operations, stable/fixture-tested extraction, safe markdown/link handling, preserved error causes, an actual session model, and reproducible packaging. The current clone builds conceptually around a live Google UI but provides no automated tests or CI evidence, so behavior should be treated as version-sensitive and operationally fragile.
