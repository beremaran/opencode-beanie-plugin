## OpenCode Patterns

### Entrypoint and Tool Registration

- The plugin uses the OpenCode `Plugin` and `tool` APIs, initializes project-scoped state during plugin startup, and returns two tools plus an event handler ([`src/plugin/worktree.ts:19-21`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L19-L21), [`src/plugin/worktree.ts:984-1012`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L984-L1012)).
- Tool arguments are declared with `tool.schema`, with descriptions that explain the AI-facing contract ([`src/plugin/worktree.ts:1011-1022`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1011-L1022), [`src/plugin/worktree.ts:1140-1147`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1140-L1147)).
- Validation is repeated at execution boundaries: branch and base-branch values are checked with Zod before any git operation ([`src/plugin/worktree.ts:1023-1036`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1023-L1036)).
- OpenCode logging is integrated through `client.app.log`, with failures intentionally swallowed so logging cannot disrupt the tool ([`src/plugin/worktree.ts:984-1004`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L984-L1004), [`src/plugin/kdco-primitives/log-warn.ts:32-51`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/log-warn.ts#L32-L51)).

### Session and Lifecycle Design

- Worktree sessions are persisted in SQLite under `~/.local/share/opencode/plugins/worktree/{project-id}.sqlite`; WAL mode and a five-second busy timeout support concurrent access ([`src/plugin/worktree/state.ts:1-9`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/state.ts#L1-L9), [`src/plugin/worktree/state.ts:143-185`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/state.ts#L143-L185)).
- State records launch mode, OCX profile, and binary path, allowing a child terminal to reproduce the parent launch context ([`src/plugin/worktree/state.ts:24-39`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/state.ts#L24-L39), [`src/plugin/worktree/launch-context.ts:98-118`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/launch-context.ts#L98-L118)). Persisted rows normalize legacy records without launch metadata to plain mode ([`src/plugin/worktree/launch-context.ts:62-78`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/launch-context.ts#L62-L78)).
- `worktree_delete` does not immediately destroy state. It records a pending operation, and `session.idle` performs hooks, `git add -A`, snapshot commit, forced worktree removal, pending-state clearing, and session removal ([`src/plugin/worktree.ts:1140-1159`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1140-L1159), [`src/plugin/worktree.ts:1163-1198`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1163-L1198)).
- Pending operations use a singleton row with `INSERT OR REPLACE`, explicitly making the behavior last-write-wins ([`src/plugin/worktree/state.ts:342-387`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/state.ts#L342-L387), [`src/plugin/worktree/state.ts:424-468`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/state.ts#L424-L468)). This is simple and crash-resilient, but concurrent sessions can replace one another’s pending operation by design.
- Session forking copies plan and delegation files and removes the forked session and destination directories if copying fails ([`src/plugin/worktree.ts:407-513`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L407-L513)). This is a strong compensating-cleanup pattern for multi-resource operations.

## Security and Reliability Lessons

- Git commands use `Bun.spawn(["git", ...args])` with an argument array, avoiding shell interpolation ([`src/plugin/worktree.ts:605-627`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L605-L627)). The same principle is used for tmux, terminal launchers, and cmux commands ([`src/plugin/worktree/terminal.ts:305-368`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L305-L368), [`src/plugin/worktree/terminal.ts:411-440`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L411-L440)).
- Branch validation blocks option injection, invalid git-ref forms, control characters, shell metacharacters, traversal-like `..`, reflog syntax, leading/trailing dots, and `.lock` suffixes ([`src/plugin/worktree.ts:83-123`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L83-L123)).
- Sync paths reject absolute paths and obvious traversal, then resolve real paths to prevent symlink escapes. Destination parents and targets are also checked for symlinks before writes/removal ([`src/plugin/worktree.ts:672-721`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L672-L721), [`src/plugin/worktree.ts:723-771`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L723-L771), [`src/plugin/worktree.ts:778-823`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L778-L823)).
- Hook commands intentionally run through `bash -c` in the worktree directory ([`src/plugin/worktree.ts:875-897`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L875-L897)). The README correctly warns that hooks run with user privileges ([`README.md:201-207`](../../repos/kdcokenny--opencode-worktree/README.md#L201-L207)). Hooks are therefore a deliberate trusted-configuration escape hatch, not a sandbox.
- Shell-specific escaping handles Bash, AppleScript, and Windows batch metacharacters and rejects null bytes ([`src/plugin/kdco-primitives/shell.ts:11-43`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/shell.ts#L11-L43), [`src/plugin/kdco-primitives/shell.ts:45-138`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/shell.ts#L45-L138)). This is preferable to treating all terminal launchers as equivalent.
- Detached terminal processes use self-deleting scripts or explicit cleanup paths, avoiding the race where a caller deletes a script before the child reads it ([`src/plugin/worktree/terminal.ts:78-97`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L78-L97), [`src/plugin/worktree/terminal.ts:616-657`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L616-L657)).
- A notable reliability pitfall is cleanup semantics after partial terminal launch: cmux reports `hasStateMutation` on timeout, preventing an unsafe fallback that could create a duplicate workspace ([`src/plugin/worktree/terminal.ts:444-506`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L444-L506), [`src/plugin/worktree/terminal.ts:1277-1295`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree/terminal.ts#L1277-L1295)).

## Configuration Lessons and Pitfalls

- `.opencode/worktree.jsonc` is auto-created with a schema URL, copy-file list, symlink-directory list, excluded patterns, and lifecycle hooks ([`src/plugin/worktree.ts:911-977`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L911-L977)). JSONC parsing is used instead of naïve JSON parsing, preserving comments safely ([`src/plugin/worktree.ts:962-969`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L962-L969)).
- The `exclude` configuration is documented and schema-validated but marked “reserved for future use” and is not consumed by the copy path ([`src/plugin/worktree.ts:132-149`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L132-L149), [`src/plugin/worktree.ts:1068-1079`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L1068-L1079)). This is an important documentation/API mismatch to avoid in new plugins.
- Invalid config syntax, schema failures, and load errors fall back to empty defaults rather than failing worktree creation ([`src/plugin/worktree.ts:964-977`](../../repos/kdcokenny--opencode-worktree/src/plugin/worktree.ts#L964-L977)). This improves availability but can silently omit intended secrets, dependencies, or hooks; the warning must be visible to users.
- Project IDs use the first root commit for stability across worktree moves, resolve shared git metadata when `.git` is a worktree file, cache under `.git/opencode`, and fall back to a path hash for non-git/failed cases ([`src/plugin/kdco-primitives/get-project-id.ts:33-57`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/get-project-id.ts#L33-L57), [`src/plugin/kdco-primitives/get-project-id.ts:78-119`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/get-project-id.ts#L78-L119), [`src/plugin/kdco-primitives/get-project-id.ts:124-171`](../../repos/kdcokenny--opencode-worktree/src/plugin/kdco-primitives/get-project-id.ts#L124-L171)). The fallback is practical, but a moved non-git project changes identity and storage location.

- Highest-value missing tests would cover branch/ref rejection, symlink and destination race cases, malformed JSONC, hook failure behavior, pending-operation replacement, SQLite migration, launch-context validation, terminal fallback ordering, detached-script cleanup, and the missing `cmux` packaging dependency.

## Bottom Line

This repository demonstrates a mature OpenCode tool design for a stateful workflow: typed tool boundaries, explicit lifecycle events, durable SQLite state, array-based process spawning, path/symlink defenses, platform-specific escaping, and compensating cleanup. Its main lesson for plugin authors is to separate AI-facing tools from durable state and external process orchestration, while making every destructive or shell-adjacent boundary explicit.

The main adoption risk is packaging, not the workflow design. The clone is a thin upstream-maintained facade with no dependency/build/test metadata, and its checked-in re-export of a missing `cmux` module makes standalone installation or verification impossible from this clone alone. Any reuse should start by retrieving the corresponding OCX registry source and package metadata, then adding an independent test/build gate before distribution.
