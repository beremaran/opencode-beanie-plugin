## What the plugin does

Subagent Reporter makes subagent progress visible in non-interactive `opencode run` output. It prefixes text and tool activity with a title-cased agent name and instance number, suppresses adjacent duplicate tool calls, and emits a finish marker when a subagent becomes idle (`README.md:5-15`; `subagent-reporter.ts:333-383`). Installation is deliberately file-based: users copy the TypeScript file into the global plugins directory and run OpenCode normally, without an npm plugin entry (`README.md:17-31`).

## OpenCode integration patterns

### Explicit output and runtime gating

- The plugin returns a default async plugin function and, when reporting is disabled, returns `{}` without registering hooks (`subagent-reporter.ts:87-92`). This is a low-impact opt-out pattern for a presentation-only plugin.
- It enables itself by default only when `process.argv` contains the `run` subcommand, rejects the TUI worker path, and provides an explicit `SUBAGENT_REPORTER_ENABLED` override (`subagent-reporter.ts:46-85`). This protects interactive rendering and avoids injecting text into other OpenCode modes such as `serve`, `web`, or ACP (`subagent-reporter.ts:62-67`).
- Output format is detected from both `--format=json` and `--format json`, with `SUBAGENT_REPORTER_FORMAT` taking precedence (`subagent-reporter.ts:20-43`). In JSON mode, the plugin emits one JSON object per line with a distinct `type: "subagent"`; in default mode it emits the legacy human-readable line (`subagent-reporter.ts:108-121`). The key lesson is to preserve the host stream’s framing rather than blindly writing plain text.

### Session topology and event handling

- `session.created` events populate a local parent map and identify the first parentless session as the root; later sessions are classified only when they are descendants of that root (`subagent-reporter.ts:257-275`, `subagent-reporter.ts:126-149`). The ancestry walk uses a `seen` set, so malformed cyclic parent links do not loop forever (`subagent-reporter.ts:135-147`).
- Agent labels are assigned per parent and agent name, with an instance counter; late agent metadata from `message.updated` is merged into an existing session before classification (`subagent-reporter.ts:170-206`, `subagent-reporter.ts:278-293`). This produces stable readable labels while accommodating event ordering where the agent is not known at session creation.
- The handler filters `message.part.updated` to known descendant subagents and handles only tool, completed text, and completed reasoning parts (`subagent-reporter.ts:295-327`, `subagent-reporter.ts:333-383`). `session.status` with `idle` is used as a one-time completion signal (`subagent-reporter.ts:295-315`).
- Tool summaries deliberately select useful fields by tool name, with a generic fallback for unfamiliar tools (`subagent-reporter.ts:216-255`). This is a practical compatibility seam, but it assumes OpenCode tool input field names and should be treated as version-sensitive.

## Configuration and operational patterns

- Configuration is intentionally environment/CLI based rather than file based. `SUBAGENT_REPORTER_ENABLED` supports explicit true/false spellings, and `SUBAGENT_REPORTER_FORMAT` supports only `json` or `default`, otherwise falling back to argument detection (`subagent-reporter.ts:20-43`, `subagent-reporter.ts:68-85`).
- The plugin has no OpenCode client calls, filesystem writes, subprocesses, network access, or persistent storage. All runtime state is closure-scoped to one plugin instance (`subagent-reporter.ts:94-106`). This keeps its integration surface small and avoids cross-process configuration or data leakage.
- The README’s manual installation instructions are short and actionable, and the example output documents the observable contract (`README.md:17-43`). It does not document supported OpenCode versions, runtime requirements, JSON event schema, environment variable precedence, or privacy implications of printing tool inputs.

## Pitfalls and security lessons

- **Stdout is a trust boundary.** In default mode, tool details and model-generated text are written directly to stdout (`subagent-reporter.ts:115-120`, `subagent-reporter.ts:340-349`, `subagent-reporter.ts:356-383`). Paths, commands, prompts, and assistant text may contain secrets or terminal control sequences. The ANSI bold wrapper is controlled by the plugin, but the interpolated detail/text is not. Redact sensitive fields, escape or strip terminal controls, and offer a safe structured-only mode when output is being captured.
- **JSON mode preserves syntax, not confidentiality.** `JSON.stringify` makes each custom event parseable, but it still serializes the full text and selected tool detail (`subagent-reporter.ts:115-118`, `subagent-reporter.ts:345-348`, `subagent-reporter.ts:367-382`). Consumers and logs should treat these events as potentially sensitive.
- **Process detection is brittle by design.** The implementation depends on observed `process.argv` shapes and a `/tui/` substring in `argv[1]` (`subagent-reporter.ts:49-67`, `subagent-reporter.ts:77-85`). OpenCode launcher changes, alternate path separators, wrappers, or embedded usage can cause false negatives or accidental output. Prefer a documented host signal if one becomes available, and retain an explicit off switch.
- **Unbounded runtime state.** Session, subagent, instance, printed-part, tool-status, last-signature, and finished-session maps/sets are created once and never evicted (`subagent-reporter.ts:96-106`). A long-lived process with many sessions or parts can grow memory indefinitely. Delete per-session entries after completion and bound dedupe history.
- **Event-order assumptions can suppress reporting.** A child created before its parent is observed, or a child whose ancestry metadata is unavailable at classification time, is ignored (`subagent-reporter.ts:175-178`, `subagent-reporter.ts:321-323`). The plugin should either retry classification when parent metadata arrives or document the required event ordering.
- **Dedupe keys have lifecycle and collision limits.** Completed text and reasoning are deduped by `${part.id}:${part.time.end}`, while tools are deduped only against the last signature per session (`subagent-reporter.ts:341-351`, `subagent-reporter.ts:356-382`). Reused IDs, missing timestamps, or identical adjacent tool calls with materially different hidden inputs can produce missing or duplicated output. Tests should encode the intended event semantics.
- **Untrusted type boundaries are broad.** The event payload is typed as `any`, and most fields are read through optional chaining and converted with `String(...)` (`subagent-reporter.ts:257-264`, `subagent-reporter.ts:319-340`). This is resilient to missing fields but gives no compile-time protection against SDK schema drift. Narrow event unions or runtime guards would make compatibility failures more visible.

## Testing lessons

There are no tests or test runner configuration in the clone, so behavior is not automatically validated. High-value unit tests could exercise `detectOutputMode` and `isReportingEnabled` across argv/env combinations, including TUI and explicit overrides (`subagent-reporter.ts:29-44`, `subagent-reporter.ts:68-85`). Event-fixture tests should cover root and nested session creation, late agent metadata, cyclic/missing parents, idle completion deduplication, repeated tool statuses, text/reasoning deduplication, unknown tool inputs, and malformed event properties (`subagent-reporter.ts:126-206`, `subagent-reporter.ts:257-383`). Output contract tests should assert that default mode always emits newline-terminated plain lines and JSON mode emits parseable one-line objects without corrupting the surrounding NDJSON stream (`subagent-reporter.ts:108-121`). Security tests should verify that control characters and sensitive tool fields are redacted or escaped if that policy is added.

## Packaging and release lessons

- This is a source-file installation rather than a published package: the README instructs users to copy `subagent-reporter.ts` into `~/.config/opencode/plugins` (`README.md:17-31`). That minimizes packaging complexity and makes the source directly auditable.
- The repository has no declared OpenCode API dependency, supported runtime version, build step, typecheck step, test gate, package allowlist, or release automation. The installation therefore relies on the user’s OpenCode/Bun TypeScript loader and provides no reproducible artifact or compatibility gate.
- The GPLv3 license is present (`LICENSE:1-4`, `LICENSE:621-648`), but the source file does not contain a copyright/license header or a pointer to the license. A published plugin should make the license and modification obligations discoverable from the installed file or README, especially for copy-based installation.
- A stronger release baseline would add a minimal package or documented versioned source distribution, pin/declare the supported OpenCode API/runtime, run typechecking and fixture tests, and verify the exact installed file and license in a clean artifact.

## Reusable takeaways

1. Gate output by host mode and return `{}` outside the intended execution path so a diagnostic plugin cannot damage the TUI (`subagent-reporter.ts:68-92`).
2. Match the host’s framing: emit valid one-line structured events in JSON mode and plain lines only for human-readable mode (`subagent-reporter.ts:108-121`).
3. Model parent/child session topology explicitly and use cycle-safe ancestry checks before reporting subagent events (`subagent-reporter.ts:126-149`, `subagent-reporter.ts:257-275`).
4. Treat event-derived text, tool inputs, and terminal output as sensitive untrusted data; protocol validity does not make content safe (`subagent-reporter.ts:226-255`, `subagent-reporter.ts:333-383`).
5. Pair closure-scoped event state with eviction, event fixtures, and a compatibility gate; the tiny source-only distribution otherwise has no automated defense against SDK or runtime changes.
