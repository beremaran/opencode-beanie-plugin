## Architecture and OpenCode patterns

- **SDK import and registration:** The only SDK dependency is a type-only `Plugin` import from `@opencode-ai/plugin`; the named `AutoTitle` export is typed as `Plugin`, with a default export for loader convenience (`src/index.ts:1`, `src/index.ts:535-537`, `src/index.ts:767`). The plugin factory receives `{ client }` and returns an event handler object (`src/index.ts:535-551`, `src/index.ts:723-765`).
- **Lifecycle/events:** It handles `message.part.updated` for an immediate fallback title and `session.idle` for AI refinement (`src/index.ts:731-761`). The event payload is treated as `unknown` at the boundary, then cast to `any`; session IDs are extracted from several possible shapes (`src/index.ts:723-729`, `src/index.ts:482-493`).
- **Context and session mutation:** It reads the current title with `client.session.get`, messages with `client.session.messages`, and changes titles with `client.session.update` (`src/index.ts:553-610`). It intentionally leaves non-default/custom titles alone, while recognizing its own prefixed titles as mutable (`src/index.ts:238-267`, `src/index.ts:619-627`, `src/index.ts:655-663`).
- **AI/provider wiring:** Configuration can pin `provider/model`; otherwise it calls `client.provider.list()` to identify connected providers and `client.config.providers()` to enumerate models, prioritizing connected providers and matching model IDs against cheap/fast patterns (`src/index.ts:157-235`). AI generation creates a temporary session, sends `client.session.prompt` with a text part and resolved model, extracts text, then deletes the temporary session (`src/index.ts:376-477`).
- **Tools/commands:** No OpenCode tools or commands are registered. The public interface is event-driven only (`src/index.ts:723-765`).
- **State/concurrency:** State is process-local and initialized per plugin instance: three session-ID sets track fallback, final, and in-flight AI work, plus a lazily resolved model cache (`src/index.ts:20-25`, `src/index.ts:544-549`). The idle handler uses `pendingAISessions` to suppress duplicate concurrent AI work and removes the marker in `finally` (`src/index.ts:643-665`, `src/index.ts:716-720`).
- **Process boundaries:** Runtime work stays in the OpenCode process and uses the SDK client; the shell installer is the only external process boundary, cloning and building the repository (`install.sh:57-93`).

## Configuration, errors, and security

- **Configuration:** All options are environment variables: explicit model/provider, max title length, disable switch, and debug output path (`src/index.ts:73-95`; documented in `README.md:134-153`). Disabled mode returns an empty plugin object without registering behavior (`src/index.ts:539-542`). Debug file paths are resolved relative to `process.cwd()`, directories are created, and startup truncates the file (`src/index.ts:97-115`).
- **Error handling:** SDK reads and title updates use `try/catch`; AI failure retains the keyword title, and temporary-session deletion is attempted both on successful extraction and in `finally` with swallowed cleanup errors (`src/index.ts:554-577`, `src/index.ts:579-610`, `src/index.ts:454-477`, `src/index.ts:702-720`). Fire-and-forget event work attaches rejection handlers (`src/index.ts:746-749`, `src/index.ts:758-760`). Logging also forwards to `client.app.log` and deliberately ignores logging failures (`src/index.ts:138-147`).
- **Strengths:** Two-phase UX gives immediate local feedback before network/model work (`README.md:17-24`, `README.md:59-107`). Custom-title protection, bounded/sanitized output, provider-aware model selection, cached model discovery, and cleanup are all explicit (`src/index.ts:270-275`, `src/index.ts:619-639`, `src/index.ts:682-715`).
- **Pitfalls/anti-patterns:**
  - `message.part.updated` does not verify the part's message role; it triggers on the first text part in a new session, despite comments saying it should identify user text (`src/index.ts:731-746`). This can title from assistant/system text or race with multiple parts.
  - The `pendingAISessions` guard is set only in the idle path. Multiple message-part events can concurrently call `handleUserMessage` before either finishes, causing duplicate reads/updates (`src/index.ts:612-641`, `src/index.ts:731-749`).
  - SDK responses and events rely heavily on `any`, including provider/model shapes and prompt responses, weakening compile-time protection against SDK drift (`src/index.ts:157-235`, `src/index.ts:409-445`, `src/index.ts:723-739`).
  - “Cheapest” is heuristic name matching, and when no pattern matches it chooses the first model, not a price-ranked model (`src/index.ts:42-71`).
  - A title can be checked as default and then overwritten after the user changes it during asynchronous work; there is no compare-and-set or second custom-title check immediately before update (`src/index.ts:619-637`, `src/index.ts:655-705`).
  - Temporary AI sessions receive truncated user and assistant content, which is an implicit data disclosure to the selected provider (`src/index.ts:385-402`). Debug logging also records message snippets (`src/index.ts:676-680`); file logging is opt-in but has no permissions hardening.
  - Installation is a `curl | bash` option and clones the mutable repository default branch with `--depth 1`; it is convenient but not reproducible or supply-chain pinned (`README.md:39-43`, `install.sh:7-8`, `install.sh:63-89`).
  - The installer uses `cd` into a temporary directory and copies generated JavaScript to the global plugin directory; it does not verify package integrity or preserve/backup an existing installation (`install.sh:63-89`).

## Reusable development-bible lessons

1. Keep the plugin boundary small: a typed factory returning lifecycle handlers is easy to discover and install.
2. Pair a deterministic local fallback with asynchronous refinement when latency matters, and make fallback behavior survive provider/model failure.
3. Guard mutable session state with explicit per-session lifecycle states, but protect every event entrypoint against duplicate work, not only the slow path.
4. Re-check user-owned state immediately before mutation; asynchronous reads must not authorize stale writes.
5. Prefer SDK response types or narrow runtime validators over broad `any` casts, especially at provider and event boundaries.
6. Treat model “cheapness,” data sent to temporary sessions, debug logs, and file permissions as explicit privacy/cost policy, not implementation details.
7. Test the returned plugin factory with mocked SDK calls and event sequences in addition to pure helpers; cover duplicate events, cleanup, failures, and user edits.
8. Make installation reproducible: pin a release/tag or package version, verify artifacts, and document upgrade/rollback behavior.
