## What the plugin does

Smart Title listens for idle sessions, extracts conversation context, asks an authenticated AI provider for a short title, and updates the session title. The README describes automatic idle-triggered updates and unified OpenCode authentication without plugin-specific API keys (`README.md:1-10`). Installation is a normal npm package plus an entry in the user's OpenCode config (`README.md:14-24`).

## OpenCode integration patterns

### Plugin entrypoint and event handling

- The package exports a default `Plugin` function, reads configuration from `ctx`, and returns `{}` when disabled (`index.ts:423-435`). This is a simple, low-impact opt-out pattern.
- It returns an `event` handler and reacts to `session.status` events whose status is `idle` (`index.ts:447-455`). The event payload is accessed with `@ts-ignore` because the author states the SDK types do not yet expose `session.status` (`index.ts:449-452`). This is pragmatic for an evolving API, but should be isolated and covered by a compatibility test.
- It uses `ctx.client.session.messages`, `session.get`, and `session.update` to inspect and mutate a session, and `ctx.client.tui.showToast` for fallback feedback (`index.ts:23-32`, `index.ts:288-308`, `index.ts:402-406`).
- Child/subagent sessions are detected through `session.get(...).data.parentID` and skipped (`index.ts:67-94`, `index.ts:456-459`). This avoids producing titles for internal/child work rather than user-facing conversations.
- The handler counts idle events per session and applies a configurable threshold (`index.ts:97-99`, `index.ts:461-479`). The actual title update is started asynchronously so the event handler is not blocked (`index.ts:487-494`).

### Context and model selection

- Message extraction filters to user and assistant roles, excludes system messages, and ignores synthetic text parts (`index.ts:127-146`, `index.ts:101-113`, `index.ts:152-199`).
- Each turn retains the user message and only the first and last assistant messages, reducing redundant assistant context (`index.ts:147-183`, `index.ts:220-242`). The final incomplete user turn is retained, which is useful when the idle event occurs before an assistant response (`index.ts:186-199`).
- A strict prompt requests a single-line title of at most 50 characters and tells the model not to assume a tech stack or respond to conversation content (`prompt.ts:4-19`). The generated result is additionally reduced to the first non-empty line, strips `<think>` blocks, and caps output at 100 characters (`index.ts:245-262`).
- The configured `provider/model` is tried first; if it fails, authenticated providers are tried in an explicit priority order with provider-specific fallback models (`lib/model-selector.ts:49-59`, `lib/model-selector.ts:60-107`, `lib/model-selector.ts:109-161`). A failed configured model is surfaced via a toast rather than silently hidden (`index.ts:288-308`).
- Heavy dependencies are dynamically imported only when title generation is needed (`index.ts:1-12`, `index.ts:315-316`, `lib/model-selector.ts:7-9`, `lib/model-selector.ts:66-68`). This is a useful startup-cost and failure-isolation pattern for plugins that are installed but not triggered often.

## Configuration and operational patterns

- Defaults are explicit (`enabled: true`, debug off, threshold 1), and configuration supports global `~/.config/opencode/smart-title.jsonc` plus project `.opencode/smart-title.jsonc` (`lib/config.ts:8-23`). JSONC is parsed with `jsonc-parser` (`lib/config.ts:2-5`).
- Resolution prefers JSONC over JSON, searches upward from `ctx.directory` for the nearest `.opencode` directory, and merges defaults, global config, then project config (`lib/config.ts:29-71`, `lib/config.ts:117-157`). This gives project settings precedence while allowing a global installation default.
- If no global config exists, the plugin creates a commented default file, making configuration discoverable (`lib/config.ts:74-101`). Invalid/unreadable files are swallowed and treated as absent (`lib/config.ts:104-114`), which preserves plugin availability but provides no user-facing diagnostic.
- Optional JSONL logs go under `~/.config/opencode/logs/smart-title/YYYY-MM-DD.log`; directory creation and writes are best-effort and logging failures are deliberately ignored (`lib/logger.ts:11-23`, `lib/logger.ts:25-47`).

## Pitfalls and security lessons

- **Unbounded context:** all non-synthetic user text and selected assistant text is accumulated, but `truncate` is only used for debug log snippets, not the prompt (`index.ts:103-113`, `index.ts:127-206`, `index.ts:373-382`). Long sessions can cause excessive token/cost usage or model failures. A production implementation should impose a total character/token budget and define which turns are retained.
- **Conversation disclosure:** the full selected conversation is sent to an external authenticated provider through `generateText` (`index.ts:311-325`). The README explains authentication but does not describe privacy, retention, provider choice, or sensitive-data handling (`README.md:5-10`). Plugins using session content should document this explicitly and offer a disable/privacy control.
- **Prompt-injection and title integrity:** conversation text is interpolated directly inside a prompt delimiter (`index.ts:318-325`). The prompt says not to respond to message content, but untrusted conversation content can still influence output. `cleanTitle` limits shape and length but does not remove control characters, markdown, or misleading content (`index.ts:248-261`). Treat generated titles as untrusted display data and test adversarial inputs.
- **Configuration validation:** `updateThreshold` is typed as a number but never range-checked (`lib/config.ts:8-18`, `lib/config.ts:147-155`). Zero makes `currentCount % config.updateThreshold` produce `NaN`, and negative/fractional values have undefined product behavior (`index.ts:461-479`). Validate finite integers greater than zero before use.
- **Concurrency and lifecycle:** idle events can launch overlapping updates because the map tracks counts but no in-flight promise or per-session lock (`index.ts:461-494`). The module-level map also has no eviction, so long-lived processes can retain session IDs indefinitely (`index.ts:97-99`). Add per-session deduplication and cleanup.
- **Sensitive logging:** debug logs include session IDs, model/provider metadata, generated titles, error stacks, and truncated user text (`index.ts:330-343`, `index.ts:373-379`, `index.ts:437-445`). Logs are written under the user's config directory without documented retention or redaction (`lib/logger.ts:13-16`, `lib/logger.ts:31-45`). Avoid content logging by default and document file permissions/retention.
- **Error handling hides configuration faults:** parse errors and filesystem errors are silently ignored (`lib/config.ts:104-114`, `lib/logger.ts:44-46`). This keeps the plugin from breaking OpenCode, but a warning/toast or one-time diagnostic would make failures actionable.
- **SDK typing drift:** `@ts-ignore` is used for the event payload (`index.ts:447-452`), and the client shape is re-declared locally with `any` return values (`index.ts:23-32`). This reduces compile-time protection when OpenCode API shapes change.

## Testing lessons

There are no test files, test script, or test dependency in the clone. The only automated checks are TypeScript compilation commands: `build` runs `tsc`, `typecheck` runs `tsc --noEmit`, and publishing invokes the build (`package.json:9-15`). The implementation has several pure seams that should be unit tested: JSONC precedence and malformed values (`lib/config.ts:107-159`), message grouping/synthetic filtering (`index.ts:101-206`), title cleaning (`index.ts:248-262`), model fallback ordering and failure behavior (`lib/model-selector.ts:60-162`), threshold/duplicate idle handling (`index.ts:461-494`), and subagent exclusion (`index.ts:71-94`). An integration test should assert the exact OpenCode event shape and that a failed toast or title update does not reject the event handler.

## Packaging and release lessons

- The package is ESM, points consumers at compiled `dist/index.js` and declarations, and requires OpenCode plugin API `>=0.13.7` (`package.json:3-7`, `package.json:36-48`).
- `prepublishOnly` builds the package, and `postbuild` removes `dist/logs` (`package.json:9-15`). TypeScript emits declarations, declaration maps, and source maps into `dist` (`tsconfig.json:11-20`).
- The npm allowlist ships only `dist/`, README, and LICENSE (`package.json:50-54`), while `.npmignore` excludes source, config, logs, lockfiles, and TypeScript configuration (`.npmignore:1-18`). This keeps the artifact small, but package-tarball CI should verify that the compiled entrypoint and declarations are actually present.
- There is no lockfile in the tracked clone and no test gate before publishing beyond compilation (`.gitignore:1-8`, `package.json:9-15`). Reproducible release builds and dependency/audit checks would improve supply-chain confidence.

## Reusable takeaways

1. Use a minimal default plugin return and an explicit disabled path so optional automation cannot interfere with OpenCode startup (`index.ts:426-432`).
2. Defer large AI/provider imports until the event actually needs them (`index.ts:315-316`, `lib/model-selector.ts:66-68`).
3. Filter synthetic/system content and skip child sessions before sending context to a model (`index.ts:101-146`, `index.ts:456-459`).
4. Make model fallback order observable and notify users when their configured model was not used (`lib/model-selector.ts:109-161`, `index.ts:288-308`).
5. Pair asynchronous fire-and-forget work with bounded context, in-flight deduplication, validated configuration, redacted logs, and tests; this plugin demonstrates the first mechanism but leaves the safeguards for downstream implementations (`index.ts:487-494`).
