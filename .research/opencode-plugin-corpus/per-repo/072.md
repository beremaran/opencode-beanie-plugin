## OpenCode integration patterns

- **Use the current v1 plugin shape explicitly.** The default export is an object with `id: 'opencode-swarm'` and `server: OpenCodeSwarm`, and the comment explains why a bare function is unsafe for OpenCode's loader (`src/index.ts:3626-3637`). This is a useful compatibility pattern for plugins that also need type re-exports (`src/index.ts:3639-3647`).
- **Return the host manifest only after bounded, fail-open initialization.** Config, snapshot, and Git-exclude work are launched in parallel and each is timeout-wrapped; errors fall back to safe defaults or non-fatal logging before `Promise.all` completes (`src/index.ts:543-617`). Expensive repository graph scanning, orphan recovery, bundled-skill synchronization, and version checks are put on a post-resolution task queue rather than blocking `server()` (`src/index.ts:726-767`, `src/index.ts:779-853`). This directly addresses plugin-host behavior where a slow unresolved entry can appear as a missing plugin (`src/index.ts:770-777`).
- **Keep hook transforms in-place where the host discards return values.** The final messages transform mutates `output.messages` in place and documents the failed rebind pattern (`src/index.ts:2584-2607`). The system transform deliberately does not collapse `output.system`, both because rebinding is ineffective and because moving cache breakpoints would damage prompt caching (`src/index.ts:2671-2683`).
- **Compose concerns at the plugin boundary.** The returned object registers agents, a generated tool object, an event observer, chat/message transforms, text completion gating, system transforms, compaction, chat-message handling, and automation (`src/index.ts:1791-1811`, `src/index.ts:2503-2619`, `src/index.ts:3619-3623`). This gives a clear inventory point, but the very large entrypoint is also a maintenance risk.
- **Persist workflow state outside process memory.** The architecture describes one architect, serialized task execution, QA before the next task, and file-backed state (`docs/architecture.md:5-14`). The README identifies `.swarm/` as the location for plans, evidence, context, knowledge, and telemetry, enabling resume across sessions (`README.md:105-123`).

## Reliability and durability lessons

- **Make the authoritative state explicit.** The plan ledger is append-only JSONL under `.swarm/plan-ledger.jsonl`, carries schema/version and before/after SHA-256 hashes, and defines a lock key for coordinated appends (`src/plan/ledger.ts:1-5`, `src/plan/ledger.ts:58-84`, `src/plan/ledger.ts:109-118`). Its atomic writer fsyncs the temporary file before rename, while documenting the deliberate omission of directory fsync (`src/plan/ledger.ts:150-168`).
- **Test concurrent writers, not just sequential persistence.** The regression tests assert that concurrent appends preserve both events and unique monotonic sequence numbers, and that compare-and-set writers produce one `LedgerStaleWriterError` (`src/plan/ledger-concurrency.regression.test.ts:33-89`). This is a strong model for any plugin that mutates project artifacts from multiple hooks or agents.
- **Bound session-keyed process state.** Heartbeat timestamps use a session-keyed map with a FIFO cap of 500 entries (`src/index.ts:206-224`, `src/index.ts:2633-2645`). The broader state module also caps task/file attribution entries at 128 and only reclaims completed entries (`src/state.ts:148-155`). Long-lived OpenCode processes should apply this pattern to every module-level map/set.
- **Defer only work that is genuinely independent.** The init code documents the ordering contract: Git exclusion must finish before `.swarm/` writes, while graph and recovery work can be deferred (`src/index.ts:561-567`, `src/index.ts:770-797`). Deferral without an explicit dependency analysis would risk writing unignored state or exposing incomplete recovery.

## Security patterns and pitfalls

- **Treat external text as hostile before LLM ingress.** `scanExternalContent` checks oversized input, invisible format characters, prompt-injection patterns, and unsafe-instruction patterns; low-trust warnings are promoted to errors and error findings are visibly wrapped as external-content threats (`src/services/external-content-scanner.ts:44-69`, `src/services/external-content-scanner.ts:120-149`, `src/services/external-content-scanner.ts:151-214`). The shared scanner is intended to cover network-fetched sources consistently (`src/services/external-content-scanner.ts:1-13`).
- **Canonicalize paths before authorization.** Full-auto policy resolves the deepest existing in-root ancestor, compares both unresolved and resolved paths against the project root, and fails closed around symlink escapes (`src/full-auto/policy.ts:404-449`). It separately checks declared scope and high-risk build paths (`src/full-auto/policy.ts:450-473`). This is a useful defense against checking only lexical relative paths.
- **Escalate shell metacharacters even for apparently safe commands.** The policy explicitly detects `|`, `&`, `;`, redirects, backticks, command substitution, and escaped newlines to prevent safe-prefix bypasses such as redirecting output or chaining destructive commands (`src/full-auto/policy.ts:476-489`).
- **Security checks should include the CI supply chain.** The workflow declares `contents: read` and pins checkout, Bun setup, and cache actions to full commit SHAs (`.github/workflows/ci.yml:19-20`, `.github/workflows/ci.yml:31-32`, `.github/workflows/ci.yml:158-168`). A dedicated Bun test statically checks expression injection, action pinning, token permissions, secret exposure, and command injection (`tests/security/ci-workflow-security.test.ts:3-10`, `tests/security/ci-workflow-security.test.ts:48-116`, `tests/security/ci-workflow-security.test.ts:168-207`).
- **Do not mistake regex neutralization or policy classification for a sandbox.** The external scanner wraps matched strings but still passes the resulting text to the model (`src/services/external-content-scanner.ts:72-99`, `src/services/external-content-scanner.ts:202-214`); the command policy's shown path is classification logic, not process isolation (`src/full-auto/policy.ts:482-489`). Plugins should retain least-privilege host permissions and independent execution boundaries.
- **Adversarial tests expose a quality caveat.** The plan-write adversarial suite describes path traversal, nulls, injection characters, oversized payloads, nesting, permissions, and malformed input, but several assertions accept any thrown error as success (`test/adversarial-plan-write.test.ts:1-14`, `test/adversarial-plan-write.test.ts:108-164`). Tests should verify the exact rejection reason and destination invariants where possible, not merely that something failed.

## Testing practices

- Tests use `bun:test` and temporary directories with cleanup hooks (`src/plan/ledger-concurrency.regression.test.ts:1-3`, `src/plan/ledger-concurrency.regression.test.ts:24-31`). The bootstrap adversarial tests exercise missing/null directories, active-call interference, and traversal-shaped paths against session initialization (`src/index.bootstrap-adversarial.test.ts:45-80`, `src/index.bootstrap-adversarial.test.ts:100-149`).
- The repository favors dependency-injection seams over global module mocking; the external-content scanner explicitly documents its `_internals` seam (`src/services/external-content-scanner.ts:8-13`, `src/services/external-content-scanner.ts:217-225`). This reduces Bun test-runner cross-file pollution.
- Test-file size is enforced as a diff-scoped ratchet: new or grown `*.test.ts` files over 500 lines fail, while existing violations do not break unrelated work (`scripts/check-test-file-cap.ts:3-39`, `scripts/check-test-file-cap.ts:118-176`). This is a practical way to control a large test corpus without requiring a risky mass split.
- CI layers typecheck, formatting, mock/invariant checks, tool-registration coherence, runtime source-reference checks, event-contract checks, and cross-contamination checks before broader validation (`.github/workflows/ci.yml:150-205`). Platform-sensitive paths opt into a three-OS matrix, addressing failures that an Ubuntu-only PR suite would miss (`.github/workflows/ci.yml:65-79`, `.github/workflows/ci.yml:122-148`).
- No test command was executed in the clone because `node_modules` is absent; the package declares `bun test` and a frozen-lockfile CI install (`package.json:88-110`, `.github/workflows/ci.yml:169-177`). This report therefore records source/test structure rather than a fresh runtime pass.

## Configuration and packaging

- `package.json` separates the Node-targeted plugin bundle from the Bun-targeted CLI: `main`/`types` point at `dist`, while `bin` points at `dist/cli/index.js` (`package.json:5-17`, `package.json:88-110`). TypeScript emits declarations from `src`, and the build copies tree-sitter grammars and emits separate bundles (`package.json:89-91`, `tsconfig.json:1-19`).
- The package allowlist explicitly ships runtime output, grammars, binaries, evaluation fixtures, selected bundled skills, README, and license while excluding source and test trees (`package.json:40-86`). The package smoke script checks required files and rejects forbidden prefixes (`scripts/package-smoke.mjs:72-100`), a strong defense against publishing an unusable or overly broad artifact.
- Release automation uses release-please, frozen Bun installation, a build, package smoke validation, and npm publication with OIDC provenance first and token fallback (`.github/workflows/release-and-publish.yml:8-24`, `.github/workflows/release-and-publish.yml:45-73`). Action SHAs and explicit permissions reduce workflow drift and credential scope.
- The `files` list and package-smoke required skill list are duplicated by design, with a test intended to detect drift (`scripts/package-smoke.mjs:13-14`). Such duplicated inventories need an automated parity check, otherwise a newly added runtime skill can work from a checkout but disappear from the npm tarball.

## Key takeaways

- Adopt the v1 `{ id, server }` export and keep initialization bounded, parallel where safe, and fail-open.
- Treat hook outputs according to the host's mutation contract; in-place mutation is essential for message transforms.
- Use durable, hashed, locked state with explicit recovery and concurrency tests when agent work spans turns or processes.
- Validate external content, canonicalize paths, detect shell syntax rather than trusting command prefixes, and constrain CI credentials/actions.
- Pair source tests with package smoke tests and frozen-lockfile release gates; verify the exact packed artifact, not only the repository checkout.
- Keep the defense claims proportional: regex scanners and policy classifiers are useful layers, but neither replaces sandboxing, least privilege, or exact behavioral assertions.
