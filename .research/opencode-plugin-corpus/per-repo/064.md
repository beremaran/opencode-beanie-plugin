## OpenCode patterns

- **Small event-driven plugin surface.** The entrypoint creates the plugin from the OpenCode `Plugin` type and returns `tool.execute.before` plus `event` hooks (`src/notify.ts:25`, `src/notify.ts:555-567`, `src/notify.ts:949-1003`). The implementation adds no tools or prompts, matching the README's minimal-context claim (`README.md:112-117`).
- **Startup-only expensive discovery.** Configuration and terminal detection are loaded once at plugin startup, and cmux availability is resolved once and retained in a runtime object (`src/notify.ts:555-568`). This avoids repeating filesystem, process, and terminal detection work for every event.
- **Meaningful-event filtering.** Child sessions are excluded by default through an OpenCode session lookup and `parentID` check; lookup failure deliberately falls back to notifying rather than silently dropping attention-worthy events (`src/notify.ts:222-230`, `src/notify.ts:429-446`, `src/notify.ts:472-490`). Permission events bypass parent filtering because they block the human (`src/notify.ts:505-517`).
- **Best-effort backend fallback.** cmux is attempted first only when its executable and workflow context are available; failures and exceptions fall through to desktop notifications (`src/notify/backend.ts:95-109`, `src/notify/cmux.ts:108-123`). Platform routing uses `alerter` on macOS and `node-notifier` elsewhere (`src/notify/backend.ts:82-93`, `src/notify.ts:385-403`).
- **Bounded external commands.** cmux commands run with argument arrays rather than shell strings, have a 1.5-second timeout, and attempt process cleanup on timeout (`src/notify/cmux.ts:125-179`). The alerter path checks `PATH`, reports a concrete install hint, waits for exit, and treats nonzero status as a fallback condition (`src/notify/backend.ts:31-79`).
- **Event de-duplication and serialization.** Question, ready, and permission events use short per-key dedupe windows (`src/notify.ts:251-253`, `src/notify.ts:313-331`, `src/notify.ts:895-947`). cmux status writes are coalesced per session and drained serially, while failed status updates disable further status writes without stopping notifications (`src/notify.ts:750-799`).
- **Graceful logging boundary.** Shared warning logging uses the OpenCode app log API when a client exists and falls back to `console.warn`; logging failures are swallowed so diagnostics cannot disrupt plugin behavior (`src/kdco-primitives/log-warn.ts:32-50`).

## Security lessons and pitfalls

- **AppleScript injection risk in configured terminal names.** `getBundleId` interpolates `processName` into `id of application "..."` without using the repository's own `escapeAppleScript` helper (`src/notify.ts:152-154`, `src/notify.ts:170-175`, `src/kdco-primitives/shell.ts:81-105`). Since `terminal` is user-configurable (`README.md:81-109`), a malicious value could alter the osascript expression. Pass arguments through a safe abstraction or escape/reject the value before interpolation.
- **Executable trust is handled thoughtfully for cmux.** Resolution rejects non-absolute paths and paths inside the working directory, temp directories, and common temporary roots, compares real paths to address symlinks, and requires the cmux workflow environment (`src/notify/cmux.ts:59-123`). This is a reusable defense for PATH-discovered helper binaries, although the same explicit trust policy should be applied consistently to every external helper.
- **Notification content is truncated but not otherwise normalized.** Session titles and error messages are sliced to 50 and 100 characters respectively (`src/notify.ts:449-457`, `src/notify.ts:492-502`), which limits volume but does not remove control characters or potentially sensitive task content. Desktop and cmux backends should treat event text as untrusted display data.
- **Configuration parsing is fail-open and unvalidated.** JSON parse errors and all other read errors silently select defaults, while valid JSON values are shallowly merged into typed configuration without checking types, time formats, sound names, or ranges (`src/notify.ts:107-130`, `src/notify.ts:198-215`). This is resilient for normal use but can produce surprising behavior, including `NaN`-based quiet-hour comparisons.
- **Repository/package drift is a delivery risk.** The source imports `./notify/status`, `./notify/title`, and `../kdco-primitives/cmux`, but those files are not present in the clone's tracked file list; the primitive index also exports `./cmux` while that file is absent (`src/notify.ts:40-45`, `src/notify/cmux.ts:1-5`, `src/kdco-primitives/index.ts:21-28`). The README lists additional absent files such as `status.ts` and `title.ts` (`README.md:135-153`). A facade should be generated atomically from its source monorepo or include a build-time completeness check.

## Testing lessons

- **No tests are included.** The clone contains no `test`, `tests`, or `*.test.*` files; `git ls-files` contains only source, README, registry metadata, and the license. Consequently, dedupe keys, quiet-hours boundaries, parent-session fallback, cmux trust checks, timeout cleanup, and platform routing have no repository-level regression coverage.
- **Pure seams are ready for focused tests.** Functions such as `buildAlerterArguments`, `sendDesktopNotificationByPlatform`, `sendNotificationWithFallback`, `resolveCmuxNotificationCommand`, and `withTimeout` accept injectable runtimes or expose deterministic behavior (`src/notify/backend.ts:34-109`, `src/notify/cmux.ts:51-179`, `src/kdco-primitives/with-timeout.ts:58-84`). Tests should assert exact argv arrays, fallback behavior, nonzero exits, timeout kills, and rejected untrusted paths without invoking real desktop helpers.
- **Lifecycle tests should cover timers.** The plugin creates busy-status and OSC-title intervals and calls `unref` when available (`src/notify.ts:619-634`, `src/notify.ts:819-841`). Tests need to verify intervals stop when sessions become idle or status writes fail, otherwise notification plugins can leak timers or retain process state.
- **The checked-out facade cannot establish a clean build/test gate.** There is no package manifest declaring the imported OpenCode, Bun, `node-notifier`, or `detect-terminal` dependencies, and the unresolved local imports prevent the tracked source from being self-contained (`src/notify.ts:22-32`, `src/notify.ts:40-45`, `src/notify/cmux.ts:4-5`). The registry metadata declares only `node-notifier` and `detect-terminal` (`registry.json:7-16`), so it is not a substitute for a clone-local compile/test configuration.

## Packaging and maintenance

- **Registry metadata is concise but inconsistent with the checked-out layout.** It declares a single source file `src/kdco-notify.ts` copied to `plugin/kdco-notify.ts`, while the clone's main implementation is `src/notify.ts` and the README documents a multi-file target layout (`registry.json:7-16`, `README.md:135-153`). Consumers need the registry generator/source-of-truth rather than assuming this facade can be packaged directly.
- **Manual installation has a high drift cost.** The README requires preserving a multi-file layout, manually installing dependencies and `alerter`, and re-copying updates (`README.md:135-159`). This is a useful fallback for users but a maintenance warning: generated artifacts should record their source revision and validate required files before publication.
- **The facade's ownership model is explicit.** Updates are directed to the OCX monorepo and users are told not to open issues or pull requests here (`README.md:165-175`). That reduces duplicate maintenance, but it also means this clone's pinned commit and generated registry metadata are critical provenance for auditing.
- **License and disclaimer are clear.** The repository includes MIT terms (`LICENSE:1-21`) and explicitly states it is not built by or affiliated with the OpenCode team (`README.md:177-183`).

## Overall assessment

`opencode-notify` demonstrates a strong event-handling design: startup caching, parent-session filtering, short dedupe windows, bounded helper processes, cmux-to-desktop fallback, and serialized status updates. The most reusable lessons are to isolate notification backends behind injectable seams, treat helper executables and display text as trust boundaries, and disable only degraded optional features when a backend fails. The checked-out facade has major reproducibility limitations: no package/test/CI metadata and imports/files that do not match the tracked snapshot, plus an AppleScript interpolation issue in configurable terminal handling. Those packaging and validation gaps are more significant than the runtime architecture's strengths for anyone intending to consume this clone directly.
