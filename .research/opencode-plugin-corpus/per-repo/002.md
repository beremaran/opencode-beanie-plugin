## Architecture And SDK Patterns

- The package exports two independent named `Plugin` implementations from a two-line barrel (`src/index.ts:1-2`). It imports the plugin SDK's `Plugin` type and `tool()` helper from `@opencode-ai/plugin` (`src/agent-self-identity.ts:1`, `src/agent-attribution-tool.ts:1-3`).
- `AgentSelfIdentityPlugin` is an async plugin factory with no configuration. It returns two experimental lifecycle hooks: `experimental.chat.messages.transform` and `experimental.chat.system.transform` (`src/agent-self-identity.ts:16-20`, `27-35`).
- The message hook finds the last user message with `findLast`, reads runtime `info.agent`, and stores it by `info.sessionID`; the system hook looks up `input.sessionID`, appends a single sentence to mutable `output.system`, then deletes the entry (`src/agent-self-identity.ts:20-35`). This is a concrete two-phase hook pattern for passing derived state between lifecycle events.
- State is plugin-instance-local and keyed by session ID (`src/agent-self-identity.ts:17`, `24`, `29`). Tests explicitly prove concurrent session isolation and last-user-message precedence (`src/agent-self-identity.test.ts:94-126`, `128-149`), including command-triggered agent switching (`151-181`).
- `AgentAttributionToolPlugin` receives the SDK `client` from `PluginInput` and registers `agent_attribution` under the returned `tool` object (`src/agent-attribution-tool.ts:10-13`). The tool declares a description and empty argument schema, then uses `context.sessionID` to call `client.session.messages({ path: { id } })` (`14-23`).
- Tool output is intentionally derived from the SDK session response: numbered user lines contain only the role, while assistant lines include `info.agent` and `providerID/modelID`, with optional `variant` (`src/agent-attribution-tool.ts:23-35`). The README explains that user `agent` identifies routing rather than necessarily the processing agent (`README.md:46-71`); the migration guide documents this as the v3 breaking output change (`MIGRATION.md:3-35`).
- There is no auth/provider wiring, command registration, process spawning, external persistence, or direct context mutation beyond the documented hook output objects and tool response.

## Types, Compatibility, And Configuration

- `src/types.ts` provides local type augmentations because the pinned SDK v1 types omit runtime `agent` and `variant` fields (`src/types.ts:1-10`). The implementation uses casts at the hook/tool boundaries to bridge that gap (`src/agent-self-identity.ts:21`, `src/agent-attribution-tool.ts:29-31`). This is pragmatic but should be removed or narrowed when SDK types catch up.
- Strict TypeScript is enabled with no emit for development (`tsconfig.json:1-12`). Declaration-only build output is configured separately and excludes tests (`tsconfig.build.json:1-12`).
- User configuration is minimal: README instructs adding the package string to `opencode.json`, and says both plugins load automatically (`README.md:22-32`). There are no plugin-specific options, environment variables, config files, or auth setup.
- Package metadata is ESM (`type: module`), exposes `dist/index.js` plus `dist/index.d.ts`, and publishes only `dist` and `MIGRATION.md` (`package.json:8-18`). The build bundles source with Bun and emits declarations with `tsc` (`package.json:20-22`).

## State, Errors, And Security

- The map avoids cross-session leakage in normal hook ordering, but entries are deleted only after a successful system transform (`src/agent-self-identity.ts:27-35`). If the second hook is skipped or throws, a stale session entry can remain for the plugin lifetime; there is no bounded cleanup or error recovery. The implementation does guard missing agent/session IDs by returning (`20-25`, `28-30`).
- SDK request failures from `client.session.messages()` are not caught or translated (`src/agent-attribution-tool.ts:20-23`). This preserves failure visibility but means tool errors depend on host behavior.
- Assistant attribution defaults a missing agent to `unknown` (`src/agent-attribution-tool.ts:29-31`), but `formatModel` assumes `providerID` and `modelID` exist (`5-8`). Malformed or future message shapes could produce `undefined/undefined`; tests cover missing agent, not missing model fields (`src/agent-attribution-tool.test.ts:123-145`).
- The tool returns only role/attribution/model metadata and does not expose message content (`src/agent-attribution-tool.ts:25-35`), which is a useful minimization boundary. It makes no network calls except the host SDK session API and has no secrets or subprocess surface.

## Strengths

- Small, composable exports let users install both behaviors while keeping each mechanism independently testable (`src/index.ts:1-2`; `README.md:12-20`).
- Session-keyed state and one-shot cleanup make concurrent hook execution understandable and testable (`src/agent-self-identity.ts:17-35`; `src/agent-self-identity.test.ts:94-126`).
- The v2-to-v3 design avoids mutating conversation text with synthetic attribution tags; attribution is on-demand through a tool (`README.md:63-71`; `MIGRATION.md:62-73`).
- Tests assert externally visible hook output and exact SDK request shape instead of only testing helpers (`src/agent-self-identity.test.ts:29-39`; `src/agent-attribution-tool.test.ts:78-85`).
- Packaging, declarations, frozen-lockfile CI, release automation, and migration documentation are all explicit (`package.json:8-29`; `tsconfig.build.json:1-12`; `.github/workflows/release-please.yml:39-50`).

## Pitfalls And Reusable Lessons

- Prefer host lifecycle hooks to preserve clean conversation data; inject only the minimum system context needed, and expose historical metadata through an explicit tool when it is needed (`src/agent-self-identity.ts:31-34`; `README.md:63-71`).
- Scope mutable plugin state by session (or another host-provided isolation key), test interleaving sessions, and add eviction/error cleanup if hook ordering is not guaranteed (`src/agent-self-identity.ts:17-35`).
- Treat SDK/runtime type mismatches as a documented compatibility layer with a tracking issue and isolated casts (`src/types.ts:1-26`).
- Keep tool output semantics conservative: do not label user routing metadata as processing attribution (`MIGRATION.md:5-10`).
- When output is intended for agent prompts, document and test its exact format, and classify format changes as breaking even when the TypeScript API is unchanged (`MIGRATION.md:37-43`; `src/agent-attribution-tool.test.ts:112-121`, `175-181`).
- Add explicit handling or tests for malformed assistant metadata and SDK failures if the plugin is expected to operate across host/version boundaries; the current code relies on required fields and propagates request errors (`src/agent-attribution-tool.ts:5-8`, `20-23`).
