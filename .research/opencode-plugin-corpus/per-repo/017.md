# Repository 017: athal7/opencode-devcontainers

## Scope and availability

- Manifest index 17 resolves to `https://github.com/athal7/opencode-devcontainers`; the inspected clone is `.research/opencode-plugin-corpus/repos/athal7--opencode-devcontainers`.
- The clone is available and was inspected without modifying it. It has no nested manifest directory or manifest file.
- README describes the project as a community, pre-1.0 OpenCode plugin for isolated branch workspaces using devcontainers or git worktrees (`README.md:1-7`).

## SDK and registration

- The package is ESM, exposes `plugin/index.js` as its main entrypoint, requires Node >=18, and depends on `@opencode-ai/plugin` (`package.json:1-6`, `package.json:27-36`).
- The entrypoint imports the SDK `tool` helper from `@opencode-ai/plugin/tool` (`plugin/index.js:1-7`). The default export and named export are the async `devcontainers` plugin function, which receives `{ client }` (`plugin/index.js:317-329`, `plugin/index.js:827-828`).
- Registration is returned as a `tool` object containing three tools: `devcontainer_exec`, `devcontainer`, and `worktree`, plus `workspaces` (`plugin/index.js:329-335`, `plugin/index.js:386-400`, `plugin/index.js:573-584`, `plugin/index.js:692-700`).
- The plugin uses `client.path.get()` during initialization to locate OpenCode's config data directory and copies command markdown files there (`plugin/index.js:54-71`). This is a useful pattern for shipping slash-command definitions alongside programmatic tools.

## Hooks, events, and context

- It uses the `tool.execute.before` hook to intercept only `bash` calls (`plugin/index.js:771-777`). The hook reads `input.sessionID`, checks the session workspace, respects an explicitly supplied workdir outside that workspace, and mutates `output.args` (`plugin/index.js:776-787`).
- Session context is persisted per OpenCode session ID. The hook routes worktree bash calls by changing `output.args.workdir`, and routes devcontainer calls by replacing the command with a `devcontainer exec` command (`plugin/index.js:800-823`).
- Tool handlers consume `ctx.sessionID`, `ctx.abort`, or `ctx.abort` via the destructured abort signal for request-scoped state and cancellation (`plugin/index.js:337-370`, `plugin/index.js:400-402`).
- Initialization starts command installation, stale-session cleanup, and old-job cleanup through a two-second best-effort timeout so slow API/filesystem work does not block plugin startup (`plugin/index.js:47-48`, `plugin/index.js:319-327`; `plugin/helpers.js:11-31`).
- No general OpenCode event subscription, message hook, auth hook, model provider, or provider credential flow is present. The only OpenCode lifecycle interception found is `tool.execute.before`.

## Tools and commands

- `devcontainer_exec` accepts a command string, requires an active session, reports pending/running/failed background jobs, executes through the core wrapper, returns stdout, and formats nonzero exit/cancellation errors (`plugin/index.js:330-383`).
- `devcontainer` supports status, `off`, removal of one/all workspaces, targeting an existing workspace, and background creation/start. It requires the devcontainer CLI and persists the selected workspace in the current session (`plugin/index.js:386-570`).
- `worktree` supports status, `off`, existing-worktree targeting, validation that the caller is in a main Git repository, and creation of a new worktree (`plugin/index.js:573-690`).
- `workspaces` lists clones and worktrees or identifies workspaces older than seven days, including uncommitted-change warnings and manual removal instructions (`plugin/index.js:692-768`).
- Markdown commands are thin prompt-to-tool adapters. They pass `$ARGUMENTS`, current `workdir`, and explicit confirmation back to the registered tools (`plugin/command/devcontainer.md:1-9`, `plugin/command/worktree.md:1-11`, `plugin/command/workspaces.md:1-8`).
- The core API is intentionally separately exported for programmatic consumers such as `opencode-pilot`, including devcontainer, jobs, clone, port, Git, worktree, workspace, and path operations (`plugin/core/index.js:1-19`, `plugin/core/index.js:22-119`).

## Auth and providers

- No authentication or provider integration is implemented. The package only declares the OpenCode plugin SDK dependency (`package.json:35-43`); all external execution is through local `git`, `devcontainer`, Docker/Podman, direnv, and filesystem operations.

## State and processes

- Session files are stored under `OCDC_SESSIONS_DIR` or `<cache>/opencode-sessions`; an in-memory cache avoids repeated reads, while writes add an `activatedAt` timestamp (`plugin/helpers.js:81-126`).
- Paths are configurable with `OCDC_CONFIG_DIR`, `OCDC_CACHE_DIR`, `OCDC_CLONES_DIR`, `OCDC_WORKTREES_DIR`, and `OCDC_SESSIONS_DIR`; defaults are under OpenCode config/cache/data directories (`plugin/core/paths.js:14-45`; `README.md:153-160`).
- Long-running container starts use persisted jobs with `pending`, `running`, `completed`, and `failed` states. Job writes use a temporary file and rename, and terminal jobs are aged out (`plugin/core/jobs.js:15-23`, `plugin/core/jobs.js:58-77`, `plugin/core/jobs.js:163-203`).
- `upBackground` validates quickly, creates a pending job, then deliberately fire-and-forgets the real start; status/error is polled through the job file (`plugin/core/devcontainer.js:278-389`).
- Port assignments are persisted in `ports.json`, protected by an atomic mkdir lock with stale-lock recovery, and checked against actual localhost availability (`plugin/core/ports.js:18-63`, `plugin/core/ports.js:65-110`, `plugin/core/ports.js:125-171`).
- Devcontainer startup allocates a port, generates an override configuration, invokes the CLI via `spawn`, and releases the port on abort/failure (`plugin/core/devcontainer.js:148-250`). Cleanup removes the labeled container, image where possible, port/job/override/clone state, and matching sessions (`plugin/core/devcontainer.js:483-609`).
- Worktrees are placed under `~/.local/share/opencode/worktree/<repo>/<branch>`, while full clones are placed under `~/.local/share/opencode/clone/<repo>/<branch>` (`plugin/core/paths.js:25-31`, `plugin/core/clones.js:33-41`, `plugin/core/worktree.js:23-31`).

## Configuration

- User configuration is JSON at `<OCDC_CONFIG_DIR>/config.json`, merged over defaults of port range `13000-13099` (`plugin/core/config.js:16-20`, `plugin/core/config.js:216-245`). README documents optional `dockerPath` and `dockerComposePath`, including Docker/Podman auto-detection (`README.md:86-98`).
- Devcontainer config supports either `.devcontainer/devcontainer.json` or root `.devcontainer.json`, detects an internal port from `forwardPorts` or `runArgs`, removes existing forwarding, and writes an override with a unique name, workspace folder, and explicit host mapping (`plugin/core/config.js:33-61`, `plugin/core/config.js:63-110`, `plugin/core/config.js:151-189`).
- `opencode.json` is only a local development configuration containing schema, model, and build-agent model; it does not register the plugin (`opencode.json:1-9`). Installation registration is documented as adding `opencode-devcontainers` to the user's global plugin list (`README.md:22-32`).

## Errors and security

- Tool handlers consistently convert missing context, invalid repository/workspace state, failed jobs, nonzero command exits, cancellation, and caught exceptions into user-readable strings (`plugin/index.js:341-383`, `plugin/index.js:405-440`, `plugin/index.js:622-687`). Removal asks for confirmation when uncommitted changes or other active sessions are detected (`plugin/index.js:181-227`).
- Most subprocesses use `spawn` with argument arrays rather than shell interpolation (`plugin/core/devcontainer.js:31-62`, `plugin/core/git.js:17-40`). Container command execution intentionally passes the user command as the argument to `sh -c` to preserve pipes/redirection (`plugin/core/devcontainer.js:123-144`).
- Bash interception shell-quotes the workspace and override paths, and supports a deliberate `HOST:` escape hatch (`plugin/index.js:110-120`, `plugin/index.js:789-823`; `plugin/helpers.js:275-307`). Tests cover shell metacharacters and injection resistance (`test/unit/helpers.test.js:275-321`).
- Gitignored-file copying is bounded to files <=100 KB, no more than ten files per top-level directory, excludes lockfiles, rejects paths containing `..`, and skips unreadable files (`plugin/core/clones.js:15-30`, `plugin/core/clones.js:54-103`). This reduces accidental dependency copying but still intentionally copies small ignored secrets such as `.env` (`README.md:16-20`; `plugin/core/clones.js:170-173`).
- Cleanup uses Docker labels containing the workspace path to avoid touching unrelated containers; the integration test explicitly verifies a decoy container remains running (`plugin/core/devcontainer.js:432-447`, `test/integration/devcontainer-remove.test.js:67-77`, `test/integration/devcontainer-remove.test.js:160-168`).
- Pitfall: `plugin/core/worktree.js` is ESM (`package.json:5`), but `runDirenvAllow` calls CommonJS `require` without importing or defining it (`plugin/core/worktree.js:91-108`). The direnv fire-and-forget path can therefore fail at runtime when `.envrc` exists.
- Pitfall: `ports.js` says writes are atomic but writes the temp file and then directly writes the target rather than renaming it (`plugin/core/ports.js:80-92`). The mkdir lock serializes cooperating writers, but a crash during the second write can leave a partial target.
- Pitfall: the top-level `install.sh` installs an older `ocdc` executable/library set from `athal7/ocdc`, using npm/curl rather than installing this package (`install.sh:1-15`, `install.sh:23-51`, `install.sh:54-88`). It should not be treated as the OpenCode plugin installation path documented in the README.
- Pitfall: `down()` only releases the recorded port and explicitly does not stop the container (`plugin/core/devcontainer.js:612-627`), so users can believe a workspace is stopped while its container remains alive.

## Reusable lessons

- Keep OpenCode registration thin: expose focused tools, put orchestration in independently importable core modules, and provide markdown commands as simple adapters (`plugin/index.js:329-768`, `plugin/core/index.js:22-119`).
- Persist session and background-operation state outside process memory when tools can launch slow work or OpenCode may have multiple sessions (`plugin/helpers.js:81-126`, `plugin/core/jobs.js:33-77`).
- A `tool.execute.before` hook can transparently redirect an existing tool such as `bash`, but it must preserve explicit workdirs and provide a clear escape hatch (`plugin/index.js:771-823`).
- Treat destructive workspace cleanup as a multi-resource transaction with warnings, explicit confirmation, and a structured summary instead of one opaque command (`plugin/index.js:181-227`, `plugin/core/devcontainer.js:503-609`).
- Use argument-array subprocess APIs, bounded file copying, labels for resource ownership, cancellation, and focused tests for shell quoting and cleanup boundaries (`plugin/core/devcontainer.js:31-62`, `plugin/core/clones.js:54-103`, `test/integration/devcontainer-remove.test.js:100-169`).
