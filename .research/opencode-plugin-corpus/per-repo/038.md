## What It Is

`micode` is an OpenCode plugin implementing an opinionated Brainstorm -> Plan -> Implement workflow with session continuity ([`README.md:6`](../repos/vtemian--micode/README.md#L6), [`README.md:22-38`](../repos/vtemian--micode/README.md#L22)). The README exposes `/init`, `/ledger`, and `/search`, while the source also registers `/mindmodel` ([`README.md:40-47`](../repos/vtemian--micode/README.md#L40), [`src/index.ts:100-121`](../repos/vtemian--micode/src/index.ts#L100-L121)).

The entrypoint is a named `Plugin` export. It initializes optional dependency checks, loads user/model configuration, constructs lifecycle hooks and tools, and returns OpenCode `config`, chat, compaction, tool-output, message/system-transform, and event handlers ([`src/index.ts:146-184`](../repos/vtemian--micode/src/index.ts#L146-L184), [`src/index.ts:310-356`](../repos/vtemian--micode/src/index.ts#L310-L356), [`src/index.ts:358-540`](../repos/vtemian--micode/src/index.ts#L358-L540)).

## OpenCode Patterns Worth Reusing

### Host configuration is merged rather than blindly replaced

- Plugin MCP servers are built separately, then spread beneath host entries, so a host entry with the same name wins ([`src/index.ts:57-97`](../repos/vtemian--micode/src/index.ts#L57-L97)). Tests explicitly protect replacement, host-only preservation, and disabling the default server ([`tests/mcp-servers.test.ts:49-79`](../repos/vtemian--micode/tests/mcp-servers.test.ts#L49-L79)).
- Agent merging preserves existing host fields such as `steps` and `maxSteps` while applying plugin fields ([`src/index.ts:130-144`](../repos/vtemian--micode/src/index.ts#L130-L144)). The test verifies user iteration limits survive the merge ([`tests/index.test.ts:7-32`](../repos/vtemian--micode/tests/index.test.ts#L7-L32)).
- The plugin demotes built-in `build`, `plan`, `triage`, and `docs` agents to subagents, then overlays its own agents while retaining other host configuration ([`src/index.ts:340-350`](../repos/vtemian--micode/src/index.ts#L340-L350)).

### Configuration has an explicit trust boundary

- JSON and JSONC are supported, with `.jsonc` preferred over `.json`; parse failures are treated as unavailable configuration ([`src/config-loader.ts:39-45`](../repos/vtemian--micode/src/config-loader.ts#L39-L45), [`src/config-loader.ts:49-83`](../repos/vtemian--micode/src/config-loader.ts#L49-L83)).
- Valibot schemas validate configuration at the boundary. Agent overrides are allowlisted to model, temperature, token/step limits, and thinking settings; arbitrary fields such as `prompt` and `tools` are discarded ([`src/config-schemas.ts:44-65`](../repos/vtemian--micode/src/config-schemas.ts#L44-L65)). The test covers rejection of those extra fields ([`tests/config-loader.test.ts:75-105`](../repos/vtemian--micode/tests/config-loader.test.ts#L75-L105)).
- Numeric compaction thresholds are constrained to 0..1 and fragment arrays are filtered to non-empty strings ([`src/config-schemas.ts:91-120`](../repos/vtemian--micode/src/config-schemas.ts#L91-L120)).
- Model overrides can be checked against models declared in `opencode.json`, with a built-in model exception and documented precedence between per-agent, host default, and plugin fallback ([`src/config-loader.ts:210-239`](../repos/vtemian--micode/src/config-loader.ts#L210-L239), [`README.md:142-162`](../repos/vtemian--micode/README.md#L142-L162)).

### Lifecycle composition and cleanup are first-class

- Hooks are constructed with `ctx`, making the OpenCode client and directory available through dependency injection ([`src/index.ts:168-201`](../repos/vtemian--micode/src/index.ts#L168-L201)).
- Session deletion cleans per-session state across think mode, PTY, reviewer, fetch tracking, and Octto browser sessions ([`src/index.ts:288-307`](../repos/vtemian--micode/src/index.ts#L288-L307)).
- Internal reviewer sessions are tracked and excluded from recursive message transformation; cleanup is attempted in `finally` ([`src/index.ts:207-248`](../repos/vtemian--micode/src/index.ts#L207-L248), [`src/index.ts:489-496`](../repos/vtemian--micode/src/index.ts#L489-L496)).
- WebSocket messages are parsed as `unknown` and validated with a discriminated Valibot schema before routing ([`src/octto/session/server.ts:38-56`](../repos/vtemian--micode/src/octto/session/server.ts#L38-L56), [`src/octto/session/schemas.ts:10-20`](../repos/vtemian--micode/src/octto/session/schemas.ts#L10-L20)). The Octto server defaults to loopback and caps WebSocket payloads ([`src/octto/session/server.ts:126-144`](../repos/vtemian--micode/src/octto/session/server.ts#L126-L144), [`src/utils/config.ts:124-140`](../repos/vtemian--micode/src/utils/config.ts#L124-L140)).

## Security and Reliability Pitfalls

- **Critical permission broadening:** the plugin unconditionally sets global `edit`, `bash`, `webfetch`, and `external_directory` permissions to `allow`, explicitly bypassing prompts ([`src/index.ts:326-334`](../repos/vtemian--micode/src/index.ts#L326-L334)). A plugin with this behavior can materially weaken a host's safety policy. A safer pattern is opt-in, scoped permissions, or preserving host-deny decisions.
- **Mutable latest MCP supply chain:** default Context7 and API-key-gated research integrations execute `npx -y` package names, including `@upstash/context7-mcp@latest` ([`src/index.ts:62-84`](../repos/vtemian--micode/src/index.ts#L62-L84)). Tests assert the `@latest` string rather than a pinned version ([`tests/mcp-servers.test.ts:27-30`](../repos/vtemian--micode/tests/mcp-servers.test.ts#L27-L30)). Pin versions and document trust/network behavior for reproducibility.
- **Arbitrary process and filesystem capability:** the PTY tool accepts an arbitrary executable, arguments, working directory, and environment ([`src/tools/pty/tools/spawn.ts:38-63`](../repos/vtemian--micode/src/tools/pty/tools/spawn.ts#L38-L63)); `spawn_agent` accepts arbitrary agent prompts and runs all requested sessions concurrently with `Promise.all` ([`src/tools/spawn-agent.ts:135-169`](../repos/vtemian--micode/src/tools/spawn-agent.ts#L135-L169)). This is powerful by design, but requires host permission controls, concurrency limits, timeouts, and resource quotas.
- **Remote-bind switch is security-sensitive:** Octto is loopback-only by default, but `allowRemoteBind` can select a configured non-loopback address ([`src/octto/session/server.ts:126-132`](../repos/vtemian--micode/src/octto/session/server.ts#L126-L132)). The reviewed server code validates message shape but shows no authentication or origin check; remote binding should therefore remain disabled unless an authenticated boundary is added.
- **Error handling can hide configuration mistakes:** invalid or unreadable `opencode.json` and `micode.json` return `null`/empty config without logging ([`src/config-loader.ts:89-103`](../repos/vtemian--micode/src/config-loader.ts#L89-L103), [`src/config-loader.ts:158-169`](../repos/vtemian--micode/src/config-loader.ts#L158-L169)). This is resilient, but silently falling back can make a security or model-selection setting appear active when it is not.

## Packaging and Maintenance Lessons

- Pinning the OpenCode SDK dependency to `1.18.9` while allowing ranges for most other runtime dependencies gives a stable host API but leaves transitive/runtime behavior less reproducible ([`package.json:45-63`](../repos/vtemian--micode/package.json#L45-L63)). A lockfile is present (`bun.lock`), but published consumers still resolve ranges unless the package manager lock is honored.
- The README provides both registry installation and local-path development instructions ([`README.md:10-18`](../repos/vtemian--micode/README.md#L10-L18), [`README.md:164-174`](../repos/vtemian--micode/README.md#L164-L174)). It also documents model syntax and precedence, which is important because agent configuration is host-specific.
- `files` includes `src` as well as `dist`, and `types` points at `src/index.ts` while the build emits declarations to `dist` ([`package.json:5-12`](../repos/vtemian--micode/package.json#L5-L12), [`tsconfig.json:6-17`](../repos/vtemian--micode/tsconfig.json#L6-L17)). This makes source distribution convenient but is worth checking against the intended consumer type-resolution path.

## Bottom Line

The strongest reusable pattern is a compositional plugin entrypoint: preserve host configuration, validate user-controlled configuration, inject narrowly scoped lifecycle hooks, and test the shipped bundle under its supported runtimes. The most important warning is that this implementation trades away OpenCode's safety prompts globally and exposes arbitrary process/agent capabilities. Any derivative should preserve the merge, validation, cleanup, and compatibility techniques while treating permissions, remote binding, process spawning, and unpinned `npx` execution as explicit opt-in security decisions.
