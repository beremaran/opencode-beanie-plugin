## Architecture And SDK Patterns

- The entrypoint is a default-exported `Plugin` function, typed with `Plugin`; it receives `{ client, directory }`, creates project-scoped storage, instantiates a manager, and returns hooks/tools (`src/plugin/background-agents.ts:15-19`, `1827-1850`).
- SDK usage is split appropriately: plugin types/tools come from `@opencode-ai/plugin`, event/message/part types from `@opencode-ai/sdk`, and the client alias derives from `ReturnType<typeof createOpencodeClient>` (`background-agents.ts:15-16`; `kdco-primitives/types.ts:7-13`).
- Three typed tools use `tool({ description, args, execute })`: `delegate`, `delegation_read`, and `delegation_list` (`background-agents.ts:1578-1677`). Tool handlers validate required session/message context and return actionable error text rather than leaking exceptions for normal validation failures (`1599-1630`, `1642-1648`, `1657-1663`).
- The plugin registers `tool.execute.before`, `experimental.chat.system.transform`, `chat.message`, `experimental.session.compacting`, and `event` hooks (`background-agents.ts:1852-1972`). It mutates hook outputs by throwing to block invalid `task` calls, appending system rules, prepending queued notifications, and pushing compaction context (`1853-1892`, `1894-1936`).
- Events are used as lifecycle signals: idle status/session events finalize work, while `message.updated` records assistant text as progress (`1938-1971`; manager methods `1194-1200`, `1497-1503`).

## Lifecycle, State, And Concurrency

- `DelegationManager` keeps explicit in-memory records, per-session lookup, terminal waiters, timeout timers, parent pending sets, notification cycles, and queued notifications (`background-agents.ts:400-416`). Statuses are explicit: `registered`, `running`, and terminal `complete/error/cancelled/timeout` (`163-168`, `375-383`). Terminal transitions are idempotent and late progress cannot regress terminal state (`586-645`).
- Delegation creates a child session with `parentID`, registers state before starting the prompt, schedules a 15-minute timeout, and runs asynchronously with `.then/.catch` finalization (`background-agents.ts:1102-1163`). The child prompt passes the selected `agent` and disables `task`, `delegate`, `todowrite`, and `plan_save` to prevent recursion/state mutation (`1139-1155`).
- Parent notifications are sent through `session.promptAsync` with a five-second race timeout; failures are queued and injected into the next `chat.message` (`background-agents.ts:773-844`). Per-delegation and all-complete notifications use cycle tokens/quiet periods to avoid duplicates and stale aggregate notifications (`694-765`, `1034-1064`).
- Reads block on a terminal waiter, enforce a grace period, trigger timeout handling if needed, then poll briefly for the artifact before returning deterministic terminal metadata (`background-agents.ts:863-883`, `1303-1373`).
- Stable readable IDs are generated and checked against both memory and existing artifact files, with 20 attempts (`background-agents.ts:885-899`). Project storage uses the root Git commit, resolves worktrees, caches under `.git/opencode`, and falls back to a path hash; Git subprocesses have a five-second timeout and are killed on timeout (`kdco-primitives/get-project-id.ts:33-57`, `59-73`, `78-109`, `111-171`).
- No mutex is used by the main manager in this snapshot. A reusable FIFO promise mutex exists, with `runExclusive` releasing in `finally`, but is not imported by `background-agents.ts` (`kdco-primitives/mutex.ts:11-16`, `56-67`, `80-120`). This is a concurrency risk for simultaneous ID generation, notification state mutation, and file writes across plugin instances/processes.

## Persistence And Context Mutation

- Results are stored as Markdown below `~/.local/share/opencode/delegations/<project-id>/<root-session-id>/`; initialization creates the project directory (`README.md:40`, `background-agents.ts:1833-1843`, `463-475`). The artifact includes title/description, ID, agent, status, session, timestamps, and result (`1262-1300`).
- Completion persists output before notification delivery (`background-agents.ts:1006-1032`), and listing merges in-memory state with `.md` files so results survive process/session restarts (`1376-1449`).
- The compaction hook carries running delegations and up to ten unread completed records, including retrieval hints and truncated prompts (`background-agents.ts:1727-1813`, `1903-1936`). System prompt rules explain routing and explicitly tell the model not to poll (`1680-1724`).
- Metadata generation optionally creates a child session and prompts configured `small_model`, parses bounded JSON, and falls back to truncated content on absent/invalid model output or any error (`background-agents.ts:43-146`).

## Safety, Errors, And Process Boundaries

- The key safety boundary is read-only-only background execution. Agent mode and `edit/write/bash` permissions are queried before delegation; write-capable agents are rejected and directed to native `task` for undo/branching semantics (`background-agents.ts:292-368`, `1070-1099`). The inverse `tool.execute.before` hook rejects read-only agents routed through native `task` (`1852-1887`).
- Nested delegation and state-changing tools are disabled in the child prompt (`background-agents.ts:1141-1154`). Timeout attempts to delete the child session before finalizing as `timeout` (`1166-1188`).
- Logging uses OpenCode `client.app.log` with a swallowed failure path, plus a file debug log; logging failures do not disrupt tool execution (`background-agents.ts:271-283`, `1551-1566`; `kdco-primitives/log-warn.ts:13-51`).
- Timeout helper semantics are documented honestly: `Promise.race` does not cancel the underlying promise (`kdco-primitives/with-timeout.ts:24-37`, `58-83`). The Git subprocess path does kill the process on timeout (`get-project-id.ts:133-140`).
- Artifact reads are scoped to a root session in memory and via a constructed path (`background-agents.ts:907-909`, `1312-1323`), but IDs are interpolated into paths after only whitespace normalization (`1306-1309`, `1456-1482`). The generated IDs are safe, yet caller-supplied IDs could contain traversal segments; path validation or basename enforcement should be added.
- `persistOutput` catches and records write failures, then notification still proceeds (`background-agents.ts:1262-1300`, `1016-1032`). This can produce a notification whose artifact is unavailable, although read fallback/deterministic status text mitigates it.

## Configuration, Auth, Providers, And Process Model

- There is no plugin-owned configuration schema, command, auth flow, provider wiring, or environment-variable contract. It reads OpenCode config only for `small_model` and agent permissions (`background-agents.ts:64-71`, `346-361`).
- Process boundaries are OpenCode child sessions, not OS workers. The only explicit subprocess is `git rev-list` in project-ID detection (`get-project-id.ts:124-145`).
- Configuration is installation/registry-driven: OCX installation is documented as `ocx add kdco/background-agents --from https://registry.kdco.dev` (`README.md:17-29`).

## Packaging, Installation, And Testing

- `README.md` documents OCX installation, optional workspace bundle, manual copying, dependency caveats, limitations, and the upstream maintenance location (`README.md:17-29`, `120-142`).
- `registry.json` declares an OCX plugin and bundled skill, targeting `plugin/kdco-background-agents.ts` (`registry.json:1-27`), but that file does not exist in this clone; the actual source is `src/plugin/background-agents.ts`. This is a concrete snapshot/packaging inconsistency to resolve before treating the facade as directly publishable.
- The clone contains only `LICENSE`, `README.md`, `registry.json`, one large implementation file, and primitive modules (`git ls-tree` at reviewed HEAD). There is no `package.json`, lockfile, TypeScript config, build script, CI workflow, test file, or dependency declaration. README mentions `unique-names-generator` as a manual-install dependency (`README.md:120-126`), while the source imports it (`background-agents.ts:17`). Reproducible installation and versioning therefore depend on OCX/upstream rather than this repository.
- No automated tests are present. The exported `testInternals` exposes `DelegationManager` and `formatDelegationContext` (`background-agents.ts:1976-1983`), which is a useful seam, but it is unexercised in this clone.

## Strengths

- Clear plugin registration and typed tool contracts.
- Explicit, idempotent lifecycle state machine with terminal-state protection.
- Persistence-before-notification ordering and restart-aware artifact listing.
- Thoughtful compaction recovery, unread tracking, retrieval hints, and notification deduplication.
- Conservative separation of read-only background work from write-capable native task execution.
- Timeouts, bounded model metadata generation, structured logging, and Git/worktree-aware project identity.

## Pitfalls / Anti-Patterns

- The facade is not self-contained: missing package metadata, dependency declaration, build/test automation, and a registry target/source mismatch undermine reproducibility.
- Large single-file implementation (1,983 lines) concentrates lifecycle, persistence, policy, and hook behavior, increasing review and regression risk.
- In-memory state is process-local; cross-process coordination is not implemented despite filesystem persistence. The available mutex is unused.
- `session.prompt` and `promptAsync` are raced/time-bounded without universal cancellation; a late underlying operation may still mutate state.
- Caller-provided delegation IDs are not constrained to safe path components before filesystem access.
- Broad catches and swallowed logging/persistence errors preserve UX but can hide operational failure; surfaced health/diagnostic status would improve debuggability.

## Reusable Development-Bible Lessons

1. Use the OpenCode plugin factory for dependency capture, return a single explicit registration object, and type SDK clients from the SDK factory rather than inventing client shapes (`background-agents.ts:1827-1850`; `types.ts:7-13`).
2. Treat hooks as data-flow boundaries: validate hook input, mutate only documented output fields, and fail fast when policy is violated (`background-agents.ts:1852-1936`).
3. Model asynchronous work with explicit nonterminal/terminal states, idempotent terminal transitions, waiters, deadlines, and observable progress.
4. Persist durable artifacts before notifying the parent, and make retrieval work from disk when memory is gone.
5. Preserve OpenCode’s undo/branching guarantees by routing write-capable agents through native task infrastructure; do not silently create detached write sessions.
6. Disable recursive orchestration and state-changing tools in delegated sessions.
7. For production plugins, ship package metadata, lockfile/build entrypoint, CI tests, versioning, and a registry target that matches an existing file; expose narrow internals for deterministic unit tests.
