## OpenCode patterns

- The entrypoint exports a `Plugin`-typed async factory and returns an object containing `event`, `permission.ask`, and `tool.execute.before` hooks ([src/index.ts:1-2](../repos/mohak34--opencode-notifier/src/index.ts#L1-L2), [src/index.ts:483-507](../repos/mohak34--opencode-notifier/src/index.ts#L483-L507), [src/index.ts:509-604](../repos/mohak34--opencode-notifier/src/index.ts#L509-L604)). This is a clear pattern for combining lifecycle events with permission and tool hooks.
- It gates non-CLI clients behind an opt-in `enableOnDesktop` setting, while treating an unset `OPENCODE_CLIENT` as CLI ([src/index.ts:27-29](../repos/mohak34--opencode-notifier/src/index.ts#L27-L29), [src/index.ts:486-490](../repos/mohak34--opencode-notifier/src/index.ts#L486-L490)). The README explains the rationale: avoid duplicate Desktop/Web notifications while allowing explicit custom-command use ([README.md:160-173](../repos/mohak34--opencode-notifier/README.md#L160-L173)).
- Event payload parsing is defensive: nested values are narrowed through `asRecord`, `getNestedRecord`, and `getStringField`, and session lifecycle/message info is extracted without assuming every field exists ([src/index.ts:37-61](../repos/mohak34--opencode-notifier/src/index.ts#L37-L61), [src/index.ts:237-267](../repos/mohak34--opencode-notifier/src/index.ts#L237-L267)). The agent-name parser also rejects non-string titles and has regression tests ([src/index.ts:138-145](../repos/mohak34--opencode-notifier/src/index.ts#L138-L145), [src/index.agent-name.test.ts:4-29](../repos/mohak34--opencode-notifier/src/index.agent-name.test.ts#L4-L29)).
- Completion handling demonstrates race-aware session state: idle events are delayed by 350 ms, sequenced, cancelled when sessions become busy/error, and classified as top-level or subagent through the SDK session API ([src/index.ts:25-35](../repos/mohak34--opencode-notifier/src/index.ts#L25-L35), [src/index.ts:375-435](../repos/mohak34--opencode-notifier/src/index.ts#L375-L435), [src/index.ts:563-576](../repos/mohak34--opencode-notifier/src/index.ts#L563-L576)). A five-minute cleanup interval bounds in-memory state growth ([src/index.ts:91-121](../repos/mohak34--opencode-notifier/src/index.ts#L91-L121)).
- Permission duplication from the event and hook paths is explicitly deduplicated with both global and per-session timestamps, then pruned ([src/permission-dedupe.ts:1-33](../repos/mohak34--opencode-notifier/src/permission-dedupe.ts#L1-L33)); tests cover same-session duplicates, hook fallback, and pruning ([src/permission-dedupe.test.ts:4-24](../repos/mohak34--opencode-notifier/src/permission-dedupe.test.ts#L4-L24)).

## Configuration and UX

- Configuration is user-owned at `~/.config/opencode/opencode-notifier.json`, with an environment override and state file colocated beside it ([src/config.ts:209-219](../repos/mohak34--opencode-notifier/src/config.ts#L209-L219)). Missing or malformed JSON falls back to a complete default configuration ([src/config.ts:262-271](../repos/mohak34--opencode-notifier/src/config.ts#L262-L271), [src/config.ts:392-394](../repos/mohak34--opencode-notifier/src/config.ts#L392-L394)).
- The loader supports global defaults, boolean or object per-event overrides, clamped volumes, minimum-duration validation, custom messages/sounds, and platform-specific options ([src/config.ts:221-259](../repos/mohak34--opencode-notifier/src/config.ts#L221-L259), [src/config.ts:273-390](../repos/mohak34--opencode-notifier/src/config.ts#L273-L390)). - Notification, sound, bell, and custom-command channels are independently controlled per event; notification/sound work is awaited with `Promise.allSettled`, while custom commands are intentionally fire-and-forget ([src/index.ts:185-235](../repos/mohak34--opencode-notifier/src/index.ts#L185-L235)). The bell channel is TTY-aware and debounced ([src/bell.ts:4-24](../repos/mohak34--opencode-notifier/src/bell.ts#L4-L24)).

## Security and correctness pitfalls

- **High, intentional local-code-execution boundary:** when enabled, configuration supplies an executable path and arbitrary arguments; the plugin substitutes event/session/project data and spawns it detached ([src/command.ts:14-29](../repos/mohak34--opencode-notifier/src/command.ts#L14-L29), [README.md:302-334](../repos/mohak34--opencode-notifier/README.md#L302-L334)). This is appropriate for trusted local configuration but should be clearly framed as equivalent to granting the configured command execution on every selected event. `spawn` without a shell avoids shell metacharacter expansion, a useful implementation property.
- **Medium:** focus integration uses several shell-string `execSync` calls, including commands containing dynamically derived search terms, window IDs, and paths ([src/focus.ts:392-420](../repos/mohak34--opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/focus.ts#L392-L420), [src/focus.ts:716-741](../repos/mohak34--opencode-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/focus.ts#L716-L741)). Current values are mostly allowlisted, numeric, or generated, but `execFile`/argument arrays would reduce future injection risk and quoting bugs.
- **Medium:** `interrupted` is part of the public event/config/message/sound/volume types and defaults, but the entrypoint maps `MessageAbortedError` to `user_cancelled` and has no dispatch for `interrupted` ([src/config.ts:7-18](../repos/mohak34--opencode-notifier/src/config.ts#L7-L18), [src/config.ts:155-192](../repos/mohak34--opencode-notifier/src/config.ts#L155-L192), [src/index.ts:567-576](../repos/mohak34--opencode-notifier/src/index.ts#L567-L576)). This dead option surface can confuse users and should either be removed or wired and documented consistently.
- **Low:** `loadConfig` accepts many values with only light type checks, including arbitrary message and custom path strings; that is ergonomic for a local config but means malformed nested values can still propagate into downstream integrations ([src/config.ts:296-390](../repos/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/config.ts#L296-L390)). A schema or stricter validation would produce clearer diagnostics.
- Ghostty payloads are deliberately stripped of semicolons and control characters before emitting OSC 9, and tests verify this boundary ([src/notify.ts:32-49](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/notify.ts#L32-L49), [src/notify.test.ts:8-23](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/notify.test.ts#L8-L23)). macOS notification text is passed as AppleScript argv rather than interpolated into the script ([src/notify.ts:231-237](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/notify.ts#L231-L237), [src/notify.test.ts:46-60](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/notify.test.ts#L46-L60)); this is a strong escaping pattern, though app activation still constructs an AppleScript string from an app name ([src/focus.ts:255-259](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/focus.ts#L255-L259)).

## Testing lessons

- Tests cover config defaults/overrides and interpolation, notification serialization/parsing, focus classification across macOS/Linux/Windows/tmux/WezTerm, permission dedupe, bell behavior, CLI detection, and agent-name extraction ([src/config.test.ts:46-99](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/config.test.ts#L46-L99), [src/focus.test.ts:4-180](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/src/focus.test.ts#L4-L180)). Pure helpers and command-argument construction make platform behavior testable without actually sending notifications.
- The package exposes `bun test` and strict `tsc --noEmit` scripts ([package.json:23-27](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/package.json#L23-L27)). In this clone, the non-mutating checks could not fully run because `node_modules` is absent: `bun test` reported 47 passing assertions but 27 failed tests/3 import errors, and typecheck reported unresolved `is-wsl` and `node-notifier` modules. This is an environment/dependency-installation blocker, not evidence of a source assertion failure.
- Remaining useful regression targets are custom-command invocation and failure handling, complete/error ordering, actual SDK event payloads, focus shell command quoting, and the undocumented/dead `interrupted` path. Current tests mostly exercise pure functions rather than the complete plugin hook lifecycle.

## Packaging and release lessons

- `package.json` declares ESM metadata, `dist/index.js` and declarations, runtime dependencies, an SDK peer dependency, and publishes only `dist`, `sounds`, and `logos` ([package.json:1-21](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/package.json#L1-L21), [package.json:36-49](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/package.json#L36-L49)). This keeps README/source/tests out of the package while retaining runtime assets.
- The build bundles `src/index.ts` for Node and explicitly externalizes `node-notifier`; `prepublishOnly` rebuilds before publication ([package.json:23-27](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/package.json#L23-L27)). The externalization makes the runtime dependency contract important: missing or incorrectly installed dependencies prevent both typecheck and tests, as observed above.
- Strict compiler settings, declarations, and a separate `bun.lock` provide a reproducible publishing baseline ([tsconfig.json:1-16](../repos/opencode-beanie-plugin/.research/opencode-plugin-corpus/repos/mohak34--opencode-notifier/tsconfig.json#L1-L16)). Ignoring `dist` avoids checked-in generated artifacts, but release validation should verify the built output includes the asset directories named in `files`.

## Bottom line

`opencode-notifier` is a mature cross-platform plugin pattern: one typed factory, multiple OpenCode hook surfaces, tolerant event parsing, explicit per-event channels, and defensive debounce/race handling. Its strongest lessons are opt-in non-CLI behavior, fail-open focus detection, pure adapter helpers with focused tests, and safe argv-based notification construction. The main follow-ups are to install dependencies before judging the test suite, remove or implement `interrupted`, replace remaining shell-string process calls, and add lifecycle/integration coverage around command execution and session races.
