## OpenCode patterns

- Keep the plugin entry module deliberately minimal. `index.ts` exports exactly one default factory because OpenCode invokes function-valued entry exports; implementation and test exports live in a transitive module (`index.ts:1-16`). This is a useful loader-compatibility rule: do not expose helper functions from the entrypoint.
- Register a custom tool with a self-contained description, schema, and async executor. `impl.ts` uses `tool({ description, args, execute })`, and the executor delegates to an injectable `executeMorphEdit` runtime (`impl.ts:244-344`).
- Use OpenCode lifecycle hooks for presentation rather than putting UI concerns in the core operation. The `tool.execute.after` hook parses result classes into branded TUI titles and adds provider/version/model metadata (`impl.ts:347-405`).
- Put routing guidance in always-on instructions, not a skill. The packaged policy explicitly calls itself canonical and recommends the OpenCode `instructions` array (`instructions/morph-tools.md:1-8`); it distinguishes `morph_edit`, native `edit`, and `write` by task shape (`instructions/morph-tools.md:10-39`). The README documents both stable and packaged instruction paths and warns that the active agent must expose `morph_edit` (`README.md:23-71`).
- Make tool behavior mode-aware. Readonly `plan` and `explore` agents are denied by default, with an explicit environment override (`src/constants.ts:7-16`; `src/execute.ts:100-109`).
- Support per-call worktree capability without importing the orchestrator. The plugin reads a `Symbol.for` capability, validates an absolute root, fails closed on malformed/proxy values, then gives that root precedence over session context (`src/adv-capability.ts:3-35`; `src/execute.ts:111-123`).

## Security and reliability lessons

- Treat model output as untrusted before writing. The execution path refuses marker-less edits for files over 10 lines (`src/execute.ts:148-163`), rejects marker leakage (`src/execute.ts:184-197`), blocks simultaneous >60% character and >50% line loss (`src/execute.ts:199-232`), and blocks dropped imported identifiers (`src/execute.ts:234-246`). All guards happen before the write at `src/execute.ts:248-264`.
- Confine file access at the filesystem boundary, not just in prompt guidance. The resolver checks lexical containment, follows symlinks for existing targets, and validates the nearest existing parent for new targets (`src/path-confinement.ts:14-27`, `:48-121`). This also fixes the common `/root` versus `/rootEvil` prefix error (`src/path-confinement.ts:15-19`).
- Preserve secrets across every error path. API keys are read from the OpenCode process environment (`src/constants.ts:21-26`), sent only as a Bearer header (`impl.ts:108-129`), and scrubbed from API errors and generic Bearer tokens (`impl.ts:41-64`, `:131-141`, `:184-198`). Stable failure kinds avoid putting diagnostic classification in secret-bearing text (`impl.ts:28-38`).
- Keep timeout coverage through response-body parsing. The abort controller remains active until JSON parsing completes, and body-read aborts are classified as `api_timeout` (`impl.ts:74-79`, `:108-169`).
- Normalize common model formatting before calling the remote merge API. A single complete outer Markdown fence is removed, while incomplete or trailing-text fences are preserved (`src/normalize.ts:1-25`).
- Return a bounded, reviewable diff rather than only success text. The result includes additions/removals, line totals, elapsed API time, and a diff capped at 3,000 characters (`src/execute.ts:256-264`; `src/diff.ts:6-46`).
- Residual risk: import preservation is declaration-aware but regex-based and supports a finite language set; unsupported extensions return no entries (`src/imports.ts:1-8`, `:71-112`). It is a useful guard, not a substitute for parsing/typechecking. Also, `resolveTargetPath` has fallback behavior when `realpathSync` fails (`src/path-confinement.ts:81-94`, `:96-121`), so deployment should ensure filesystem errors are not silently treated as canonicalization success.

## Testing lessons

- The test suite directly imports production helpers and injects filesystem, clock, API, logging, and path dependencies into `executeMorphEdit`, enabling no-network tests (`src/execute.ts:63-69`; `index.test.ts:1143-1549`). This avoids the historical test-oracle duplication described in `docs/repo-improve-prep.md:52-64`.
- Tests cover documentation and packaging contracts as well as runtime behavior: instruction routing and tool exposure (`index.test.ts:29-78`), release-version consistency across package/README/changelog/runtime (`index.test.ts:80-149`), and cross-surface recovery-policy drift (`index.test.ts:151-213`).
- Safety coverage is scenario-oriented: marker leakage and truncation (`index.test.ts:298-488`), path resolution (`index.test.ts:950-1142`), missing keys/readonly blocks/marker refusal/unsafe output/write failures/success (`index.test.ts:1143-1551`), secret scrubbing and timeout/error classes (`index.test.ts:1552-1875`), ADV capability handling (`index.test.ts:1876-2066`), and concurrency/runtime guards (`index.test.ts:2067-2148`).

These are dependency-state failures, not observed assertion failures. The repository improvement note records prior installed-state verification, but that historical note is not a substitute for a current run (`docs/repo-improve-prep.md:100-102`).

## Packaging and release lessons

- Declare the actual packaged surface explicitly. `package.json` includes `index.ts`, `impl.ts`, `src/`, README, license, and `instructions/` (`package.json:11-17`), preventing the always-on policy from being omitted from an install.
- Keep the package manager policy coherent. The package declares Bun, tracks `bun.lock`, and exposes `check`/`ci` scripts combining typecheck, lint, formatting, and tests (`package.json:5-27`). `.gitignore` explicitly permits `bun.lock` while excluding competing lockfiles (`.gitignore:19-21`).
- Use strict TypeScript and reproducible CI commands, but ensure dependencies are installed before interpreting failures. The config enables `strict` and Bun types (`tsconfig.json:1-15`); CI and release both use `bun ci`, tests, and typecheck (`.github/workflows/ci.yml:14-28`; `.github/workflows/release.yml:14-28`).
- Release automation derives notes from the version tag and changelog, then uses the GitHub token with contents write permission (`.github/workflows/release.yml:10-13`, `:30-54`). The release-metadata tests enforce that the package version, README pin, runtime version, and changelog section agree (`index.test.ts:80-149`).
- Pin plugin installations for deterministic deployments. README shows both an unpinned Git source and a version pin (`README.md:27-42`); the latter is the safer production pattern. The package version is currently `1.11.0` (`package.json:2-3`).

## Recommended takeaways

1. Export only the OpenCode plugin factory from entry modules.
2. Separate tool registration, execution orchestration, pure guards, and presentation hooks so high-risk behavior can be injected and tested.
3. Enforce worktree confinement and secret scrubbing before any model-backed write.
4. Ship routing policy as packaged, always-on instructions and test documentation/configuration contracts for drift.
5. Treat dependency-install failures separately from test failures; a clean lockfile and a runnable isolated verification environment are release prerequisites.
